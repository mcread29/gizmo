# Synthesis

> **Status of this page:** engineering synthesis. Unless wording explicitly says that a paper reported a result, the design and recommendations below are our inference across sources, not a result claimed by one paper.

## Operational distinction: context, state, and memory

| Term        | Operational meaning                                                                                                                                                                                             | Correctness authority                                                                                                                                     |
| ----------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Context** | The bounded representation supplied to a particular model call: instructions, recent turns, selected evidence, state views, plans, and tool schemas. It is an ephemeral _read view_.                            | Never authoritative merely because it is in the prompt.                                                                                                   |
| **State**   | The current machine-interpretable facts needed to execute correctly: repository/worktree version, counters, entities, obligations, approvals, resource handles, pending actions, test status, and side effects. | External environment plus validated typed records and deterministic update rules.                                                                         |
| **Memory**  | Information retained across calls/tasks/sessions: raw events and artifacts, plus derived facts, summaries, episodes, reflections, workflows, and skills. It is a versioned _retention and retrieval subsystem_. | Observation/attempt records are authoritative about what was recorded, not necessarily ground truth; derived memory has scoped confidence and provenance. |

A transcript can carry context, reveal state, and be retained as memory, but these roles should not be conflated. A sentence generated by the model does not become a fact merely because it is copied into a future prompt.

## Strongest conclusions supported by evidence

### 1. Long context is not equivalent to usable memory

On LongMemEval's 500 questions, four long-context model settings reading roughly 115K-token histories lost 30.7%–66.3% accuracy relative to oracle evidence, depending on model and Chain-of-Note setting. The benchmark's retrieval experiments also show that a Llama-3.1-8B reader degrades sharply above about 3K retrieved tokens while GPT-4o can benefit beyond 20K: the retrieval budget belongs to the _reader_, not only the retriever. [M01, Figure 3b; §§5.2, 5.5] Lost-in-the-Middle independently found U-shaped position sensitivity on controlled multi-document QA and key–value retrieval. [M04, Figures 5–7; pp. 157–173]

**Synthesis:** retrieval should optimize evidence coverage under a reader-specific budget and place the highest-trust, highest-utility evidence where the reader uses it reliably. “Fits in the window” is not a quality criterion.

**Claim/evidence trace:** [MC001](claims/MC001.md) ← [ME001](evidence/ME001.md)/[M01](source-notes/M01-wu-longmemeval.md); [MC002](claims/MC002.md) ← [ME002](evidence/ME002.md)/[M04](source-notes/M04-liu-lost-middle.md); [MC004](claims/MC004.md) ← [ME004](evidence/ME004.md)/[M01](source-notes/M01-wu-longmemeval.md).

### 2. Raw evidence plus derived keys/views is safer than replacing raw evidence

In LongMemEval, condensed fact, keyphrase, or summary keys used alone generally underperformed original values. Concatenating extracted user facts with the original value improved average recall by 9.4% and final QA accuracy by 5.4% across the tested readers; replacing sessions/rounds with summaries or facts usually hurt, except fact decomposition for multi-session questions. [M01, Figure 5; Table 3; §§5.2–5.3] LoCoMo similarly found observation retrieval useful while session-summary retrieval did not significantly improve QA despite high retrieval recall, attributed to detail loss. [M02, Table 3; §6.1]

**Synthesis:** keep raw events/artifacts and make summaries, facts, indexes, and graphs materialized views with handles back to sources. Do not make a lossy view the sole copy.

**Claim/evidence trace:** [MC005](claims/MC005.md) ← [ME005](evidence/ME005.md)/[M01](source-notes/M01-wu-longmemeval.md); [MC006](claims/MC006.md) ← [ME006](evidence/ME006.md)/[M01](source-notes/M01-wu-longmemeval.md), [ME007](evidence/ME007.md)/[M02](source-notes/M02-maharana-locomo.md), qualified by [ME008](evidence/ME008.md)/[M08](source-notes/M08-packer-memgpt.md).

### 3. Retrieval is conditionally useful; always retrieving is not a safe default

Repoformer found cross-file retrieval helpful on roughly 20% of repository-completion cases, neutral on more than 60%, and harmful on roughly 20%. [M06, Figure 3; §5.1] Accuracy-preserving gate operating points yielded roughly 27–33% online-serving speedup; the main roughly 71% point had a small quality loss. [M06, Table 3; Appendix E.3, Table 8] ContextBench found no consistently dominant coding-agent scaffold and weak precision/F1 even when relevant context was encountered; agents often dropped previously observed gold evidence. [M03, Tables 2–5; RQ1–RQ3] In ExpeL, random experience retrieval reduced ALFWorld success from 59.0% to 42.5%. [M11, Table 3]

**Synthesis:** gate retrieval by estimated value, task stage, store density, and reader budget; rerank for applicability and trust, not semantic similarity alone; expose “no useful evidence” as a valid outcome.

**Claim/evidence trace:** [MC008](claims/MC008.md) ← [ME010](evidence/ME010.md)–[ME011](evidence/ME011.md)/[M06](source-notes/M06-wu-repoformer.md); [MC014](claims/MC014.md) ← [ME019](evidence/ME019.md)/[M03](source-notes/M03-li-contextbench.md); [MC015](claims/MC015.md) ← [ME020](evidence/ME020.md)/[M03](source-notes/M03-li-contextbench.md); [MC021](claims/MC021.md) ← [ME027](evidence/ME027.md)/[M11](source-notes/M11-zhao-expel.md).

### 4. Cheap compaction is a strong baseline; summaries are not reliably superior

Across five SWE-agent/model configurations on all 500 SWE-bench Verified tasks, observation masking cut instance cost substantially and LLM summaries did not significantly or consistently beat it. For Qwen3-Coder-480B, masking scored 54.8% at $0.61/instance versus summary 53.8% at $0.64 and raw 53.4% at $1.29. For Gemini-2.5-Flash-thinking, both compactors significantly reduced accuracy, with summary worse (31.4%) than masking (36.4%) and raw (40.4%). [M07, Tables 1, 3–4; §§4.1–4.4] ContextWeaver reports that summarization hurt GPT-5 and Gemini-3-Flash relative to a five-turn window, while dependency selection helped only when graph construction was good. [M17, Table 1; §§4.2–4.6]

**Synthesis:** first prune or mask bulky re-fetchable observations, preserve recent full turns and durable handles, and summarize only when necessary. Evaluate the summary against an omission baseline, not only raw history.

**Claim/evidence trace:** [MC016](claims/MC016.md) ← [ME021](evidence/ME021.md)/[M07](source-notes/M07-lindenbauer-complexity-trap.md); [MC017](claims/MC017.md) ← [ME022](evidence/ME022.md)/[M07](source-notes/M07-lindenbauer-complexity-trap.md); [MC018](claims/MC018.md) ← [ME023](evidence/ME023.md)/[M07](source-notes/M07-lindenbauer-complexity-trap.md); [MC019](claims/MC019.md) ← [ME024](evidence/ME024.md)/[M17](source-notes/M17-wu-contextweaver.md).

### 5. Applicable, validated experience can help; mismatched or unvalidated experience can harm

ExpeL improved ReAct from 63% to 70% in HotPotQA→FEVER transfer and from 40.0% to 59.0% on ALFWorld, but adding unvalidated Reflexion text reduced HotPotQA from 39% to 29%, and random experience retrieval reduced ALFWorld to 42.5%. [M11, Tables 1–3; Figure 5] AWM reported 35.5% WebArena success versus its in-paper accessibility-tree baseline of 15.0%; 23.5% is an external published BrowserGym HTML+accessibility-tree result. Its cross-template subset is 20.5%→33.2%, but the online success gate is partly model based and comparisons are not call matched. [M12, Tables 1–2; §§3.1.1–3.1.3] Assay found an uncurated library could reduce GPT-5.1 AppWorld challenge TGC from 52.5% to 49.9%; per-task causal masking and curation raised it to 66.4%. [M18, Table 1; Figure 3; §3.2]

**Synthesis:** experience retrieval needs two gates: objective promotion (did it work?) and applicability matching (is it helpful _here_?). Similarity is insufficient.

**Claim/evidence trace:** [MC020](claims/MC020.md) ← [ME025](evidence/ME025.md)/[M11](source-notes/M11-zhao-expel.md), qualified by [ME026](evidence/ME026.md)/[M09](source-notes/M09-park-generative-agents.md); [MC021](claims/MC021.md) ← [ME027](evidence/ME027.md)/[M11](source-notes/M11-zhao-expel.md); [MC024](claims/MC024.md) ← [ME031](evidence/ME031.md)/[M12](source-notes/M12-wang-awm.md); [MC026](claims/MC026.md) ← [ME033](evidence/ME033.md)/[M18](source-notes/M18-wang-assay.md).

### 6. Reflections are hypotheses, not facts

Reflexion reported HumanEval improvement with verbal feedback, retries, and generated tests, but the comparison was not compute matched; faulty generated tests produced an MBPP regression from 80.1% to 77.1%. [M10, Tables 1–3; §4] A cost-focused reproduction found simpler retry/warming policies could dominate reflection/search agents on the HumanEval cost–accuracy frontier. [M25, Table A1; §§2.2–2.3]

**Synthesis:** store reflections separately, link them to the failed event and oracle, and require later evidence before promoting them to durable rules.

**Claim/evidence trace:** [MC022](claims/MC022.md) ← [ME028](evidence/ME028.md)–[ME029](evidence/ME029.md)/[M10](source-notes/M10-shinn-reflexion.md); [MC023](claims/MC023.md) ← [ME030](evidence/ME030.md)/[M25](source-notes/M25-kapoor-agents-matter.md).

### 7. Explicit temporal/state roles address a real failure class, but graph memory is not universally better

A-TMA's fixed-reader/fixed-budget overlay labels current, historical, and transition evidence. On 800 LTP probes, Graphiti/Zep+A-TMA raised conflict accuracy from 0.480 to 0.720 and overall QA accuracy from 0.524 to 0.635; on full LoCoMo, temporal F1 rose from 0.0295 to 0.1705, but several other host/metric results were flat or worse. [M16, Tables 2–4; §§5.2–5.3] Mem0's graph variant improved temporal judge score (55.51→58.13) but did not improve single-hop or multi-hop results and roughly doubled its memory footprint (7K→14K tokens per conversation). Full context scored roughly 73% overall versus about 67% for base Mem0 and 68.44% for graph Mem0, showing that full context can win in this setting when its cost is acceptable. [M15, Tables 1–2; §§4.1, 4.3, 4.5]

**Synthesis:** use graphs or typed temporal records only for relation/update queries that need them. Their key benefit is explicit identity, relation, and state role—not the word “graph.”

**Claim/evidence trace:** [MC028](claims/MC028.md) ← [ME035](evidence/ME035.md)/[M16](source-notes/M16-shi-atma.md); [MC031](claims/MC031.md) ← [ME038](evidence/ME038.md)/[M16](source-notes/M16-shi-atma.md); [MC032](claims/MC032.md) ← [ME039](evidence/ME039.md)–[ME040](evidence/ME040.md)/[M15](source-notes/M15-chhikara-mem0.md).

### 8. Memory systems enlarge the security and privacy boundary

AgentPoison achieved average 81.2% malicious retrieval and 62.6% end-to-end attack success while reducing benign utility by only 0.74% across tested agent/retriever combinations; fewer than 0.1% of database entries were poisoned. [M21, Table 1; §4.2; Appendix A.1] A later EHR study found realistic clean memories could reduce one attack dramatically, but also found model-based trust defenses either rejected every candidate (empty memory) or accepted 54 poisoned entries at trust 1.0. [M24, Tables 1–2; §§8.1–8.2] AgentDojo and CaMeL v2 show that retrieved/tool content must be treated as untrusted data and that information-flow enforcement can reduce tested attacks, at material utility/token cost. [M22, Tables 3–5; M23, §6]

**Synthesis:** access control, source identity, taint/trust labels, capability policy, write validation, tenant isolation, deletion, and audit are mechanical controls, not prompt instructions.

## Three-layer reference architecture

### Layer 1 — authoritative record of observations and attempts

Recommended append-only records of observations, actions, outputs, errors, evaluator/verifier results, and side effects. They are authoritative about what was observed or attempted, not automatically about environment ground truth.

Minimum envelope:

```text
event_id, tenant/user/task, actor, timestamp,
causal_parent_ids, environment/tool/model/harness versions,
operation + normalized arguments, result status,
artifact URI + content hash, side-effect/approval record,
visibility/retention class, integrity signature
```

Normative engineering properties—not findings directly established by TapeAgents—include:

- immutable payload; corrections are new events;
- artifacts stored once and referenced by content-addressed handles;
- deterministic replay where the environment permits it;
- redaction/deletion represented by restricted tombstones and cryptographic/object deletion, not by silently rewriting history;
- source type and trust/taint travel with every read.

TapeAgents directly motivates trace attribution and replay, but its headline 8B-versus-405B economics bundle tapes with supervised distillation and are not a tape ablation. Integrity, ACL, and immutability are engineering requirements here, not TapeAgents effectiveness findings. [M14, §2; Tables 4–5; Figure 6]

### Layer 2 — materialized working state

Typed, queryable current state derived from events and reconciled with authoritative tools/databases:

```text
entities and stable IDs
current values + valid_from/valid_to
plans, obligations, owners, deadlines
resource/artifact handles
pending/approved/completed side effects
verifier/test status and unresolved failures
version vector / optimistic concurrency token
```

**Normative systems synthesis:** only deterministic operations mutate it: `create`, `patch-if-version`, `supersede`, `invalidate`, `merge`, `tombstone`, `expire`, `reconcile`. Enforce schemas, referential integrity, idempotency keys, cardinality/counts, temporal ordering, and authorization in code. An LLM may propose an operation; it does not directly mutate arbitrary records. The cited agent experiments do not directly establish this detailed transactional design.

### Layer 3 — derived experience

Summaries, extracted facts, episodes, reflections, workflows, runbooks, and executable skills. Every item carries:

```text
derived_id, type, content/code, source_event_ids,
source artifact hashes, generator/model/prompt version,
confidence and uncertainty, applicability predicate,
validation oracle + runs + held-out set,
created_at/last_verified/expires_at,
supersedes/contradicts, owner/ACL,
release version and rollback target
```

These are indexes and reusable hypotheses. A retrieval result expands to source evidence when action or verification needs exact details.

## Recommended controls

### Memory-write gate

1. **Classify** proposed write: raw event, state update, fact, preference, episode, reflection, workflow, executable skill.
2. **Authorize** tenant, actor, namespace, retention class, and write capability.
3. **Ground** every derived claim in source event/artifact IDs; reject untraceable writes.
4. **Verify** objective claims with an independent oracle where possible (tests, database state, policy checker, human approval).
5. **Check** schema, identity, temporal order, contradiction, secret/PII policy, injection/taint, and duplicate/idempotency key.
6. **Route** uncertain/reflection content to quarantine; never promote it as authoritative state.
7. **Promote** workflows/skills only after repeated success on held-out tasks and a no-skill/cost-matched ablation.
8. **Log** the decision, validator version, and rollback pointer.

### Retrieval and reranking policy

- Form stage-specific queries from task, active entities, repository/tool structure, temporal view, and unresolved obligations.
- Run lexical + dense retrieval when identifier/exact-string and semantic evidence both matter; add graph/structural traversal only for dependency or relation questions.
- Deduplicate by artifact/span and near-duplicate content; diversify across evidence roles/sources.
- Filter by tenant/ACL, time validity, version, trust/taint, and state role _before_ model reading.
- Rerank on topical relevance, applicability, reliability, novelty, evidence coverage, and predicted marginal utility.
- Return provenance and handles; order instructions separately from untrusted evidence.
- Permit `NO_RETRIEVAL` and re-retrieval after a tool result, failed test, entity resolution, or changed subgoal.

### Reader-specific token budgets

Calibrate per `(reader model, task stage, evidence type)` using an evidence-coverage × success curve. Reserve protected slots for instructions, current typed state, active plan/obligations, latest failures, and verifier feedback. Let exploration receive breadth; action receive exact local evidence; verification receive diff, tests, and acceptance criteria; handoff receive typed state plus raw handles. Stop adding items when held-out marginal success becomes zero or negative.

### Stale-memory invalidation and conflicts

- Bind repository memories to commit/tree hashes, APIs to schema/version, and user facts to temporal intervals.
- On source change, invalidate dependent derived views through provenance edges; re-verify lazily or eagerly by risk.
- Never silently overwrite: keep `supersedes`, `contradicts`, and state-role links.
- Deterministic policy resolves known-safe cases (newer authoritative record, explicit user correction, environment truth); otherwise preserve both and request arbitration.
- Query semantics choose current, historical, or transition view explicitly. [M16]

### Workflow/skill promotion

Require: objective success; no unauthorized side effects; reproducible execution; parameterization and applicability predicate; dependency/version declaration; sandbox and static checks for code; multiple runs; held-out tasks/repositories/domains; baseline and cost comparison; canary release; expiry and rollback. Failures may be retained as diagnostic episodes, never as executable skills.

### Multi-agent ownership

As normative distributed-systems guidance, use one authoritative state service, single-writer or compare-and-swap ownership per entity/task partition, explicit leases, idempotent operations, and append-only messages/events. Handoffs transfer a typed snapshot version, obligations, ACL, unresolved conflicts, and source handles. Do not ask agents to merge competing prose summaries. M20 v2 shows that extra-agent/message-passing systems can underperform a single agent under equal reasoning-token caps ([MC035](claims/MC035.md)); extra-agent benefit emerged only when information was severely partitioned or masked ([MC036](claims/MC036.md)). It does not test the durable state service recommended above. [M20, Table 1; §§5.1, 5.3]

### Privacy and deletion

- Namespace by tenant, user, project/repository, purpose, and sensitivity; deny cross-namespace retrieval by default.
- Minimize writes and separate secrets/PII from embeddings and general experience stores.
- Apply retention schedules to raw and derived data; provenance permits cascading deletion/re-indexing.
- Deletion means object removal from primary store, caches, vector/graph indexes, derived views, replicas, logs where legally permitted, and future training/export queues; retain only policy-approved non-reconstructive tombstones.
- Test deletion by seeded canaries and post-delete retrieval/extraction attempts. The reviewed agent-memory literature does **not** establish robust end-to-end deletion or unlearning guarantees. ([MC044](claims/MC044.md))

### Release-regression tests

Pin model, prompt, retriever, embedding model, tokenizer, tool schemas, harness, memory policy, and index version. On a private suite measure: task success/partial progress; retrieval recall/precision/F1/NDCG and evidence use/drop; write precision/recall; update/state-role correctness; stale/contradiction leakage; repeated-run `pass^k`; tokens/calls/latency/dollars/storage; poisoning/injection; tenant isolation; delete completeness; rollback. Compare raw, window/mask, summary, raw+derived, and oracle-context baselines under equal call/token/latency ceilings.

## Defaults by task type

| Task                     | Recommended default                                                                                                   | Escalate when                                                                                      |
| ------------------------ | --------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------- |
| Repository coding        | Structural/lexical+dense search; recent turns; mask old tool output; exact file/diff/test handles; commit-bound state | Cross-file/dependency task: dependency graph; recurring verified fixes: workflow/skill             |
| Browser/tool transaction | Authoritative environment/API state; stage-specific retrieval; policy/approval ledger; untrusted-content taint        | Repeated task templates with execution-grounded workflow evidence                                  |
| Persistent assistant     | Raw session events + fact-augmented keys; typed temporal/entity records; explicit current/history query               | Relation-heavy questions: graph view; large store: multi-key/time filtering                        |
| Long-running research    | Append-only sources/actions; claims ledger; summary for navigation only; raw citation handles                         | Dependency/paging when source graph and task phases become large                                   |
| Multi-agent system       | Shared event/state service, partitions/leases, typed handoffs, private scratchpads                                    | Add agents only for true information/tool partition, parallel latency, or independent verification |

## Known failure modes

- evidence retrieved but dropped or not used [M03];
- middle-position evidence ignored [M04];
- over-retrieval distracts smaller readers [M01, M02];
- summary erases errors, paths, identifiers, or obligations [M01, M02, M07, M17];
- stale/old/current facts coexist without state roles [M16];
- random but similar experience is inapplicable [M11];
- reflection or generated tests encode a false diagnosis [M10, M11];
- skill effects reverse across tasks and cancel globally [M18];
- graph/index maintenance duplicates data or delays freshness [M15];
- learned policy overfits a small development stream [M19];
- shared memory can spread poison [M21–M24] or create ownership races (the latter is systems risk, not evaluated by M20);
- model-based write/trust judges are confidently wrong [M24].

## What remains unproven

- that recursive summaries alone preserve all action-critical details over indefinite horizons;
- that MemGPT-style model-managed paging beats a well-tuned harness-managed policy at equal calls/tokens/latency;
- that one graph-memory design consistently beats raw+hybrid retrieval across task types;
- that learned memory managers transfer without online regret or development-set overfit;
- that automatically optimized context policies generalize beyond public benchmarks and a pinned model/harness;
- that durable shared multi-agent memory improves task performance; M20 only tests extra-agent/message-passing variants under equal reasoning-token caps;
- robust cross-user isolation, secret non-retention, and complete deletion/unlearning guarantees ([MC044](claims/MC044.md));
- storage/build/update economics at production scale for most academic systems.

## Research agenda

1. Factorial raw-event vs summary vs facts vs typed state vs graph comparisons with identical retrieval/readers.
2. Equal-token, equal-call, equal-latency and equal-dollar trials, including a longer-context and retry baseline.
3. Private held-out repositories/users/domains plus model/harness transfer and temporal future splits.
4. Memory-write datasets with source-grounded precision, update correctness, deletion, and contradiction labels.
5. Causal evidence-use tracing: observed, retrieved, included, cited, acted on, and verified.
6. Store-growth studies with update/build/storage cost, routing collisions, expiry, and garbage collection.
7. Adversarial tests for poisoning, indirect injection, cross-tenant leakage, rollback, and deletion.
8. Pre-registered repeated-run studies reporting variance and failures, not only best pass@1.
