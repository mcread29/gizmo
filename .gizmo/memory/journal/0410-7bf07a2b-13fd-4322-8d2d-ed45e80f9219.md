Yes, a handful of things I saw along the way and left alone.

- **A `marked` renderer crash floods the console.** Every markdown render with a link throws `Cannot read properties of undefined (reading 'parseInline')` from `apps/app/src/lib/features/conversation/markdown.ts:32`. The custom link renderer uses `this.parser`, which newer `marked` versions no longer bind. There were hundreds of these in the console. Links still render because marked catches it, but it is noise and likely costs time on long transcripts.

- **Snapshot `lastEventId` was never meaningful before today.** The server stamped it with the hub's counter while each socket renumbered events from one, so the replay cutoff on a thread switch compared two unrelated sequences. It happened to work only because a single connection since boot keeps the numbers aligned. That is fixed as a side effect of the heartbeat work, but it is worth knowing it was silently broken.

- **`session.resume` is used as a read.** `readSession` in the store resumes a session to inspect it, then resumes the active one again to undo the side effects. On the server, resume touches the last-session pointer, may activate a runtime, and now emits a state event. A read-only `session.read` request would be cleaner.

- **The web extension registry is add-only.** `registerWebExtensions` never drops an extension that is no longer served. After an unlink, the codex web module stays loaded and only disappears from the UI because `enabledExtensionIds` no longer includes it. Fine today, but any leaked module state persists until reload.

- **Project events are filtered by session id on the client.** Project status and extension events carry the session id of whoever registered the watch, and the client discards events whose session id is not the current one. If a watch was registered under a different session, its updates are dropped. I did not see it bite, but it is fragile.

- **The activity indicator can be hidden by any extension.** One `setWorkingVisible(false)` from any extension hides the titlebar and transcript indicator for the whole session. That is what removed the "Thinking" readout earlier while the composer still said streaming. A per-extension scope, or ignoring it once the session state says streaming, would avoid the contradiction.

- **`store.sessionStates` resets to idle on every connect.** The connect path sets every known session to idle before resync fixes the current one. Other sessions that are actually streaming show idle in the sidebar until their next state event.

- **The stray `word-wrap-issue.png`** you dropped at the repo root is still untracked.

None of these were in scope, so none are changed.
