## The fix

`session-transcript.ts:62` created every tool call as `status: 'running'` and relied on a matching `toolResult` to settle it. When a turn aborts mid-stream that result never arrives — and since this view is **rebuilt from the session file on every load**, the call reads as running forever. Reloading wouldn't have helped, and neither would restarting. I was wrong about that earlier.

Now, after the branch is read, any unsettled call gets resolved:

- Only the **newest assistant message** can still have tools in flight, so anything older with no result is finished.
- Even the newest can't be running if the provider reported `stopReason: "aborted"` or `"error"`.
- Everything else becomes `error` / **"Interrupted"**.

Two cases it deliberately preserves: a genuinely executing tool on the latest turn stays `running` (tools execute *after* their message is written), and sibling calls in a batch stay running when only one has returned.
