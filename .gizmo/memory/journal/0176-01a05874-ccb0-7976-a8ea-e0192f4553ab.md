## assistant

From **0.84.2 → 0.84.4**, the meaningful changes for Gizmo are:

### High impact

- **Native PowerShell tool on Windows** (`0.84.3`)
  - Gizmo already exposes `powershell` in its tool-policy UI, but 0.84.2 does not provide the underlying built-in tool.
  - Upgrading would make that setting functional.

- **Safer compaction behavior**
  - Large tool results now trigger compaction before another provider request.
  - Threshold compaction works when providers omit usage data.
  - Truncated compaction/branch summaries are no longer persisted.
  - Summarization no longer exposes tools or forces `toolChoice: "none"`.
  - New `session_compact_failed` events provide better failure details.

- **Session integrity fixes**
  - Resuming JSONL sessions without a trailing newline no longer risks corrupting the next entry.
  - Extension messages can no longer be inserted between a tool call and its result.

- **Windows reliability**
  - Shell abort no longer crashes if `taskkill.exe` is unavailable.
  - Several Windows input and path-handling fixes are included.

### Potential Gizmo integration improvements

- **Extension UI prompt lifecycle events** (`0.84.4`)
  - New `ui_prompt_start` / `ui_prompt_end` events distinguish active model work from waiting for user input.
  - Gizmo could use these to represent “waiting for confirmation/input” instead of leaving the session looking actively busy.

- **Extension cleanup**
  - Failed extension factories now properly remove subscriptions, provider registrations, and default state.

- **Nested skill discovery**
  - Skills inside grouped `.agents/skills/` directories are now discovered correctly.

### Provider/model fixes

Numerous fixes cover OpenAI-compatible reasoning replay, Anthropic fallback, Bedrock, Vertex proxies, Mistral tool calls, Copilot authentication, model catalogs, and thinking-level metadata.

### Upgrade caveat

Gizmo carries a custom patch against exactly `0.84.2`:

```text
patches/@earendil-works__pi-coding-agent@0.84.2.patch
```

It adds `fullTurnBoundaries` and custom compaction budgeting. Those changes are **not present in vanilla 0.84.4**, so the patch must be rebased and retested rather than simply updating the dependency. The only identified breaking API change—`GoogleThinkingLevel` → `GoogleApiThinkingLevel`—does not appear to be used by Gizmo.
