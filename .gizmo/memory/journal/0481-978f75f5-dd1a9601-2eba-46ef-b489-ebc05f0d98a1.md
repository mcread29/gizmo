## assistant

Yes — fixed, deployed, and verified. Here's what it took.

**The chain had three breaks, all the same shape: a project's override was read but then overruled by the global state.**

1. `ProjectIntegrationResolver` — `piById.get(id).enabled && (override ?? true)` made the global flag a gate, so a workspace could switch an extension *off* but never *on*. Now the override decides, with the global state as the default.
2. `enabledPiExtensionPaths` — even once resolved as enabled, the extension's code was never loaded for the session. It now takes an enabled set as well as a disabled one, threaded through session create, resume and reload.
3. `extensions.web` — the bundle list is global (no project), and it withheld any bundle for a globally-disabled extension. So a workspace could enable an extension whose UI could never arrive. It now ships anything some workspace enables; the client already gates tabs per project.
