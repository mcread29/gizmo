# Plan: `ollama` extension — local model management for Gizmo

## Context that shapes the design

- Extensions live in the **gizmo-registry** repo (cloned at `~/.gizmo/registries/gizmo-registry`), one directory per extension with `index.ts` + `pi-extension.ts` (default-exported Pi factory) + optional `src/web/index.ts` built into `<id>.web.js`, declared in that repo's `gizmo.registry.json`, and installed by linking from **Settings → Extensions**.
- Gizmo's model picker is **session-scoped** (`model.catalog` / `model.select` protocol messages), and Pi flushes pending `pi.registerProvider()` calls from extension factories when a session's services are created. So an extension can make models selectable without touching Gizmo core — the natural hook is **`pi.registerProvider("ollama", ...)`** with a `refreshModels` callback that queries Ollama live.
- Ollama ships a local REST API that covers everything: `GET /api/tags` (installed models), `POST /api/pull` (NDJSON streaming download progress), `DELETE /api/delete`, `GET /api/show` (params, context length, quantization), `GET /api/ps` (loaded/running models). Serving is OpenAI-compatible (`/v1`), which Pi already speaks via `api: "openai-completions"`.

## Architecture — three surfaces, one extension

1. **Pi provider** (in `pi-extension.ts`, async factory): registers an `ollama` provider with `baseUrl: http://localhost:11434/v1`, `api: "openai-completions"`, and a `refreshModels` that maps `/api/tags` → Pi models (context window from `/api/show`'s `model_info.*.context_length`, `cost: 0s`, `input: ["text"]`). Zero persistence needed — the catalog is always live. Models appear in the per-session model picker and are fully usable as the session model.
2. **Server extension** (`gizmoExtension.list`/`invoke`): the management RPC surface — `status`, `list`, `show`, `pull` (starts a tracked background pull job), `pull-status`, `cancel-pull`, `remove`, `ps`. One concurrent pull; a small in-memory job registry holds streaming progress from `/api/pull`, polled by the UI.
3. **Web extension** (`gizmoWebExtension`): a **settings card** (Settings → Extensions, alongside Git/Svelte etc.) as the primary management surface — installed-models list with sizes/params, pull form with a free-text tag field plus suggested-models shortcuts, live progress bar, delete with confirmation, "Ollama not running / not installed" states. Optionally a `statusBar` dot when Ollama is up, and a `commands` palette entry ("Ollama: manage models") that opens it. No inspector tab — Ollama is machine-global, not per-project, so it shouldn't ride the workspace-activated `activate()` path.

## New surface: Ollama host lifecycle management

**Server ops added to the invoke surface**

- `host.status` — merges three probes into one result: installed? (`ollama --version` + known install paths), server reachable? (`GET :11434/api/version`), current version vs. latest available.

- `host.update` — same flow when installed version < latest.
- `host.latest` — resolves latest version via the **GitHub releases API** (`api.github.com/repos/ollama/ollama/releases/latest`, tag like `v0.5.7`) — no HTML scraping, no auth needed for unauthenticated clients within rate limits.

**Platform matrix** (all server-side, in the agent-server process)

| Platform | Install/update method |
|---|---|
| Windows | `OllamaSetup.exe` from GitHub releases → run with `/VERYSILENT /NORESTART` (it's Inno Setup; installs per-user to `%LOCALAPPDATA%\Programs\Ollama`, no admin needed). Detection via that path + `--version`. |
