## Design Specificity Verdict: **Authored** (8.5/10)

This does not read as AI slop. It reads as a codebase written by someone who has opinions and wrote them down as comments next to the CSS that enforces them. The evidence is in the *decisions*, not the palette:

- **The tool-call card that disappears** (`tool-call-parts/container.css`): a completed, collapsed tool call loses its border, background, and radius entirely and becomes a single line (`[data-state='complete']:not([open])` → `background: transparent`). Running and failed calls keep the card. This is an information-density opinion you will not find in a generated UI, which would wrap every tool call in an eternal identical card.
- **State-specific microcopy instead of disabled grey**: `Composer.svelte` derives a `notice` ("Compacting context. Sending resumes when it finishes." / "Not connected to Gizmo. Reconnect to send messages.") shown *above* the input rather than silently greying the send button. The placeholder itself changes to "Steer the response while it runs…". A generated UI disables the button and calls it a day.
- **The send button that changes meaning**: `ComposerToolbar.svelte` swaps Send → Stop (danger, square icon) + Steer (primary, corner-down-left) while streaming, with distinct tooltips ("Add direction without interrupting the run"). That's a mental model about agent runs expressed in chrome.
- **The `--space-7`-style decisions in prose**: comments like "The time is a caption, not a header: hug it to the text" (`messages.css`) and "A finished, collapsed call is one line of information; giving it a card costs more vertical space than it carries" are authored reasoning.
- **Anti-cliché hygiene**: no gradients except the one functional composer fade (`composer-wrap`), no glassmorphism (backdrop-blur only on the jump-to-latest pill and dialog overlay, both legitimately transient), no emoji anywhere (Lucide throughout), no symmetric card grids — `settings.css` explicitly strips cards on resource pages: "Resource pages are work surfaces, not stacks of cards." The workspace home uses a *fact strip* of pills (`workspace-facts`), not tiles.

Where it drifts toward category-generic:

- **Empty states are thin and interchangeable.** `thread-empty` in `Conversation.svelte` is "New thread / Ask about your workspace to start." — one bold line + one sentence, centered. No suggested first actions, no workspace context injected ("Ask about gizmo-agent…"), no recent-thread affordance. It's the restrained version of the emoji empty state, but it's still the *same shape*.
- **Settings is structurally a shadcn settings page**: 232px left nav with icons + `setting-field` rows of label-left/control-right with hairline dividers. The execution is cleaner than most, but the skeleton is the default pattern.
- **Dead second empty-state system**: `ConversationPlaceholder.svelte` ("Ready when you are" + brand mark) is rendered inside `MessageList`, but `Conversation.svelte` already intercepts `empty` and `messagesLoading` and never mounts `MessageList` in either state. Two competing empty-state designs, one of which is effectively unreachable — the sign of a UI that changed its mind and didn't clean up.
- The **user bubble** (right-aligned, `14px 14px 4px` radius, `surface-soft`) is a chat idiom the design doc explicitly warns against ("consumer-chatbot styling"). It's executed quietly, but it's still the one spot where Gizmo looks like every chat app, and it fights the otherwise document-like transcript.

## Nielsen's 10 Heuristics — 31/40

1. **Visibility of system status — 4.** Exceptional, this is the app's core competency: `StreamingIndicator` with a live elapsed counter ("A long Unity compile behind a static label reads as a hang; count it out" — the comment *is* the heuristic), pulsing `session-running` dot per sidebar thread, `project-dot` connection state in titlebar, `UsageMeter` with warn/full color shifts, compaction notices, skeleton transcripts, and `MessageList`'s unread counter with a "N new messages" jump pill.
2. **Match between system and real world — 3.** "Compact context," "steer," "threads," "workspaces" are consistent agent-native vocabulary. But `Conversation.svelte`'s header still says "Thread" as an eyebrow while the sidebar and everything else says threads/workspaces, and "Agent resources" (Settings nav) vs. the "Instructions & tools / Skills / Extensions" segmented control is two taxonomies for one place.
3. **User control and freedom — 4.** Escape dismisses everything hierarchically (`App.svelte` `dismiss`), stop-with-partial-output is preserved ("Stop the response and keep what has been written"), arrow-up recalls the last prompt, rejected sends hand the text back (`Composer.send` re-hydrates the draft), ConfirmDialog puts Cancel first and focuses it, rename/delete/copy/export everywhere via context menu.
4. **Consistency and standards — 3.** Token discipline is real (`data-ui` + variables everywhere; radii and type scale never hand-rolled except the composer's `border-radius: 14px` and the agent-question's `13px` — both off-scale, inexplicably). Docked against it: the 10px font sizes (below your own 11px floor, three files), and accent used on non-interactive `workspace-fact` icons and the "Preview" badge, diluting the One-Accent Rule.
5. **Error prevention — 3.** ConfirmDialog scoped copy is genuinely good ("Your skills, workspaces, and threads are not affected" on Restore defaults). Delete is blocked during streaming (`canDeleteThread`). Missing: no confirmation *or* undo on deleting a thread with high message counts (context menu → beginDelete), and the context-range dual slider is the only destructive-ish control with no visible numeric validation.
6. **Recognition rather than recall — 3.** Tooltips carry shortcut hints (`Settings · ⌘,`), palette footer shows kbd hints, sidebar rows show message count + last-active. But the shortcut list lives in About → Settings (`AboutSettings.svelte`) and is **missing ⌘F (Find in thread)**, which exists in `shortcuts.ts` — the one doc that exists is already stale.
7. **Flexibility and efficiency of use — 4.** Nine shortcuts including asymmetric panel toggles (⌘B/⌘⇧B), command palette with workspace mode, drag-to-reorder workspaces saved server-side, `/`-commands with typeahead in the composer, send-on-enter configurable, steering mid-stream, "Collapse tool calls" bulk action.
8. **Aesthetic and minimalist design — 4.** The collapsed-tool-call flattening, the receding chrome (titlebar center replaces "N extensions" with streaming activity when working), and the workspace facts strip are exactly "quiet workbench." The one indulgence: `message-meta` reserves a 26px min-height row for a hover-only copy button, so every message pays vertical rent for an action most users will use twice.
9. **Help users recognize, diagnose, recover from errors — 3.** `ConversationError` anchors above the transcript so it can't scroll away (comment: "an error that scrolls away with the messages is an error the user cannot act on") with an inline Reconnect. Toasts copy the clipboard failure honestly. Weakness: tool *errors* inside transcripts are only a tinted border + icon; a failed tool's error text requires expanding the card — the failure surface is quieter than its importance warrants.
10. **Help and documentation — 2.** The About shortcut list is the entire help system, it's already out of date (no ⌘F), and it renders "Ctrl/⌘" as a literal string rather than detecting platform like `shortcutHint()` does elsewhere — two conventions for the same thing on two screens.

## Cognitive Load

Good overall. The shell has exactly three persistent regions and the titlebar center collapses to one line of truth. Decision points rarely exceed 4 visible options: conversation header shows Tree + overflow menu (6 items inside — acceptable, and Delete is tone-marked and streaming-disabled). Settings nav is 7 items in 2 groups with a scoped "This device" vs "Gizmo" split — honest grouping.

Two load hotspots:
- **The composer toolbar** (`ComposerToolbar.svelte`): attach, model select, thinking-level select, usage meter, compact-now, stop/steer — that's 5–6 controls in a 36px strip, several of them compact selects with transparent borders that only reveal affordance on hover. Model + thinking level is two decisions per message for most users who never change them.
- **Memory bridges**: nothing tells you what "Compact context now" will *do* until you've read the Settings → Context page; the tooltip "Compact context now" doesn't say it truncates history. The usage meter's `title={view.detail}` is the only explanation, and tooltips are hover-only.

## Emotional Journey

- **Peak**: The "N new messages" primary pill after scrolling up mid-stream (`MessageList.svelte`) — the app noticed you fell behind and offers exactly one recovery action. That's a delight moment.
- **Peak (quiet)**: Arrow-up in an empty composer recalling your last prompt — the forgiveness moment every dev tool should have and few do.
- **Valley**: Thread deletion. Context menu → confirm dialog → gone. No undo toast, no "thread deleted / Undo." For an irreversible action on accumulated work, the emotional floor drops to nothing and nothing catches it.
- **Valley**: Connection loss mid-stream. `ConversationError` appears with Reconnect (good), but streaming state, draft, and the running dot all drop simultaneously; there's no "your draft is safe" or "reconnected — resuming" reassurance that the transition preserved anything.
- **Reassurance at high stakes**: the Restore-defaults ConfirmDialog is the model — scoped description, explicit "are not affected" list. Apply that pattern to thread deletion.

## Specific Strengths

1. **Runtime state is the decoration** (`StreamingIndicator`, `project-dot`, `session-running`, `UsageMeter`, `tool-call[data-state]`). Every colored pixel maps to a real condition — success/warning/danger/accelent are never aesthetic. This is why the UI feels trustworthy: you can paint the whole app grayscale and still know what's happening. It's the design doc's "expose real runtime state not decoration" implemented as CSS selectors over live store state.
2. **The focus system** (`primitives.css`): focus is opt-out, not opt-in — `:focus-visible` applies a ring to *everything* by default, plus `[data-ui='menu-item']:focus` (correct for bits-ui's roving focus), plus `:focus-visible { position: relative; z-index: 1 }` with the comment "Rings must never be clipped by an overflow ancestor." That last rule fixes a bug most design systems ship with forever.
3. **ConfirmDialog's defaults** (`packages/ui/src/ConfirmDialog.svelte`): Cancel renders first *and* takes default focus, with the comment "a modal whose only button is the destructive one is a misclick away from data loss." Small file, exactly right values.

## Priority Issues

**P1 — Type floor violation: 10px text in three shipped styles.**
`composer-parts/editor.css:109` (`attachment-chip small`), `dialogs-parts/command-palette.css:83` (palette footer kbd), `dialogs-parts/workspace-picker.css:232`. `tokens-base.css` literally comments "11px is the floor: nothing in the UI goes smaller." Your own spec, broken in the attachment chips users stare at after pasting an image. Fix: replace with `var(--text-2xs)`; if the chip needs to be smaller, shrink the chip, not the type.

**P1 — Accent fails AA for text; faint text fails outright.**
`--color-accent: #d54f35` is **4.20:1** on white, 4.04:1 on surface — used for markdown links (`markdown.css`), active thread titles (`sessions.css` `[data-ui='session-item'][data-active]`), and palette-selected labels at 12–14px non-bold: below the 4.5:1 AA threshold for normal text. Worse, `--color-text-faint: #7d8375` is **3.91:1** on white / 3.76:1 on surface, and it carries 11px semantic content: message timestamps, session sub-labels, streaming elapsed, `titlebar-center` `[data-ui='muted']`, hljs comments. Sam cannot read session timestamps. Fix: darken accent to ~#c43f26 (≥4.5 on white), and reserve `text-faint` for decorative text only — timestamps and session metadata move to `text-muted` (4.97:1).

**P1 — Undefined token: `var(--space-7)` doesn't exist.**
`workspace-dashboard.css:189`: `margin-top: var(--space-7)` on `[data-ui='workspace-recent']` — the token is never defined in `tokens-base.css` or any theme. The declaration is invalid at computed-value time, so the section margin silently resolves to 0 and the Threads list hugs the facts strip. Fix: use `var(--space-6)` or define `--space-7: 40px` (and grep for other phantom tokens while you're there).

**P2 — Thread deletion has no undo.**
`SessionSidebar` context menu → `sessions.beginDelete` → ConfirmDialog → gone. Compare with Restore defaults, which gets the careful scoped description. A thread is *more* irreversible than a settings reset. Fix: optimistic delete + toast with a 6s Undo (the toast queue in `toasts.svelte.ts` already supports tones; add an action slot), or at minimum state the message count in the confirm copy.

**P2 — Two dead/conflicting empty-state systems.**
`ConversationPlaceholder.svelte` ("Ready when you are") is mounted inside `MessageList.svelte` but unreachable — `Conversation.svelte` renders its own skeleton/`thread-empty` instead of `MessageList` in both states. Delete `ConversationPlaceholder` or route both states through one component; right now the next contributor will "fix" whichever one they find first. Also upgrade `thread-empty` itself: inject the workspace name and one suggested action ("Ask about {workspace} — or ⌘K to open a different one").

## Persona Red Flags

**Alex (impatient power user)** — mostly served (9 shortcuts, palette, steering, arrow-up recall). Failure: **⌘F/Find-in-thread is undiscoverable** — it's in the overflow `…` menu and not in the About shortcut list (`AboutSettings.svelte` omits it), so Alex will never learn it exists. Second: message copy and tool output copy are hover-revealed (`opacity: 0` until `[data-ui='message']:hover`); there's no accelerator to reach them without mouse-hover → tab-hunting. Fix: add ⌘F to the shortcut list, and give the transcript search a "copy match" affordance or surface message actions via keyboard focus on the message itself.

**Sam (accessibility)** — the focus-ring system and `aria-live` on streaming messages, `aria-activedescendant` on the composer command menu, persistent toast live region, and `inert` on the hidden sidebar are all above-bar. Failures: (1) the contrast numbers above — `text-faint` at 3.76:1 carrying 11px metadata, accent titles at 4.2:1; (2) **color-only status in the titlebar**: `[data-ui='project-dot']` is a bare 7px span with no `aria-label`, and its three states (green/warning-pulse/grey) are hue-only at 7×7px — the compensating text ("Local agent ready") lives in the sidebar footer, invisible when the sidebar is collapsed; (3) `[data-ui='session-running']` is announced via `aria-label="Agent working"` on an empty span inside a 7px dot — verify that survives as announced content; a `visually-hidden` "· working" in the row text would be robust.

**Riley (stress tester)** — strong skeleton work and the error banner that refuses to scroll away. Failures: (1) **no virtualization grace at extreme scroll** — `estimateSize: 220` is decent, but a mis-estimate on a giant pasted-code message causes visible jump during fast scroll with `overscan: 2`; acceptable, but a jump-to-latest pill positioned at the magic `bottom: 128px` (`conversation.css`) will overlap a fully-grown composer (280px max) once attachments + notice stack up; (2) **failed tool calls under-report**: `data-state='error'` gets a tinted border and a red X, but the actual error text is behind a click — a crashed run looks calmer than it should; (3) refresh mid-stream: the router restores the workspace route and re-selects correctly (`App.svelte` effect re-syncs `router.workspacePath` — nice), but a streaming thread reopened after refresh shows whatever the agent persisted with no "this run was interrupted" marker — the transcript just ends mid-thought.

## Minor Observations

- About page renders "Ctrl/⌘" literally instead of using `shortcutHint()`'s platform detection used in tooltips on the very same screen.
