## How the built prod version is served today

`pnpm web:server start` runs `scripts/web-server.ts`, which spawns two processes:

1. **agent-server** on `127.0.0.1:8787`, with a WS origin allowlist built as `http://<host>:<webPort>` from `GIZMO_WEB_HOSTS` (default `localhost,127.0.0.1`)
2. **`vite preview`** on port 4173 serving `apps/app/dist`, proxying `/agent` → `ws://127.0.0.1:8787`

## What portless would need from it

Portless runs your command as a foreground child, assigns it a random `PORT` (4000–4999), and proxies `https://<name>.localhost` → `127.0.0.1:PORT`. Against this setup:

1. **The script is daemon-style, not a foreground server** — but it already supports a foreground verb (`tsx scripts/web-server.ts run` re-executes the supervisor), so `portless gizmo tsx scripts/web-server.ts run` would work as the portless child.

2. **Port injection** — portless sets `PORT`, but the script reads `GIZMO_WEB_PORT`. One-line fix: fall back to `process.env.PORT` before the 4173 default. (The script passes `--port` to Vite explicitly, so no Vite-side injection is needed.)

3. **The origin allowlist is the real change.** Portless terminates TLS itself, so the browser sends `Origin: https://gizmo.localhost` — no port, https scheme. But `web-server.ts` only computes origins as `http://<host>:<port>`. You'd need to let `GIZMO_WEB_HOSTS` carry scheme-aware entries (e.g. `https://gizmo.localhost`), or auto-append the portless origin when `PORT` is present. The same host list also feeds Vite's `allowedHosts`, which takes bare hostnames, so entries need light parsing either way.

4. **Windows caveats** — first run has to trust a local CA and bind port 443. The docs only mention auto-elevation on macOS/Linux (`sudo`); on Windows that's a UAC-elevated first run (your `Invoke-Elevated.ps1` path would cover it if portless doesn't handle it itself).

5. **One thing to be aware of:** the portless proxy binds **loopback only** by default. Your prod server is also reached over Tailscale MagicDNS names (the `allowedHosts` comment in `vite.config.ts` exists precisely for those). Tailnet devices would keep using the existing MagicDNS URL; portless would only give you the local `https://gizmo.localhost` name unless you explicitly enable LAN mode.

So: technically yes — roughly a scheme-aware host list, a `PORT` fallback, and `portless gizmo tsx scripts/web-server.ts run`. What's the draw for you — the HTTPS/HTTP-2 locally, consistent URLs with dev, or something else?
