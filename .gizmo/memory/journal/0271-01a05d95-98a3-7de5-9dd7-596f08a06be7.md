## Summary

The current architecture still gives one enabled extension privileged ownership of the workspace. `createWorkspaceView()` selects the first extension with `createView`, and that extension can replace workspace identity, titlebar state, inspector header state, default panel, and editor actions.

## Recommended minimal structural refactor

### 1. Make `WorkspaceView` app-owned

Keep `workspace-view.ts`, but remove registry lookup and construct only generic metadata from `AgentStore`:

- selected workspace path/name
- app connection state
- tool activity
- generic subtitle such as `Workspace`

Remove from `WorkspaceView`:

- `domainId`
- `canOpen`, `open`, `refresh`
- `pill`
- `panel`

Remove entirely:

- `WorkspacePanel`
- `GizmoWebExtension.createView`
- `load-web-extension.ts:127` validation for `createView`

This keeps the existing shell data flow while eliminating the owner slot.

### 2. Flatten every inspector contribution

In `WorkspaceInspector.svelte`:

- Activate descriptors belonging to enabled extensions.
- Flatten every runtime’s `inspectorTabs`.
- Append or merge static `inspectorTabs` from every enabled web extension.
- Render all contributions through one identical panel branch.
- Remove:
  - `domainExtensionTabs`
  - `standaloneExtensionTabs`
  - `activeDomainPanel`
  - owner panel insertion
  - nested `extensionTabs` props
  - owner-derived context kind and pill

Use the first available peer tab as the default rather than hard-coding `git`. Add an app-owned empty state when no enabled extension contributes a panel.

Preserve all tab metadata. The current mapping drops `shortLabel` and `badgeTone`, although `packages/ui/src/Tabs.svelte:7-12` supports both. This currently prevents Unity’s danger badge tone from reaching the tab shell.

Require globally unique tab IDs; installed runtime extensions mostly already namespace them (`unity.console`, `subagents.panel`, `workflows.panel`).

### 3. Restore the simple runtime return type

Return `WebExtensionRuntime[]` from `activateProjectExtensions()` and dispose them directly. Runtime ownership is still implicit in activation/scoped RPC and does not need to shape presentation.

### 4. Keep the titlebar generic

`Titlebar.svelte:103-108` should display only app-owned workspace metadata. Existing `statusBar` contributions remain the correct peer mechanism for extension-specific information.

Remove the Unity-specific global context-menu actions, or later introduce a generic context-menu contribution API. Unity already exposes equivalent actions through its panel and commands, so retaining hard-coded owner callbacks is unnecessary for the minimal refactor.
