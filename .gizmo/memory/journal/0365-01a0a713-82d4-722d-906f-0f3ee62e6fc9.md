## Setup (one time)

1. Dash → **My Profile → API Tokens → Create Token** → use the **Edit zone DNS** template, scoped to `init0.link`. Least privilege, and note: this **same token** later does Caddy's DNS-01 challenges (same `Zone:DNS:Edit` permission covers both jobs — one token for everything).
2. Grab the **Zone ID** from the `init0.link` overview page.

## The records

The one gotcha that matters: **`proxied: false`** (grey cloud, DNS-only). Orange-clouded would send clients to Cloudflare's edge, which can't reach a `100.x` origin — silently broken. With proxying off, the name resolves publicly but only connects over the tailnet, which is exactly what you want.

```bash
export CF_TOKEN=<token> ZONE=<zone-id>

for rec in "gizmo.genge 100.105.88.93" "gizmo.forge 100.68.72.45" "gizmo.outpost 100.68.130.1"; do
  set -- $rec
  curl -s -X POST "https://api.cloudflare.com/client/v4/zones/$ZONE/dns_records" \
    -H "Authorization: Bearer $CF_TOKEN" -H "Content-Type: application/json" \
    --data "{\"type\":\"A\",\"name\":\"$1.init0.link\",\"content\":\"$2\",\"ttl\":1,\"proxied\":false}"
  echo
done
```

Verify with `nslookup gizmo.genge.init0.link` from any machine (tailnet or not — it should resolve everywhere; it just only *connects* from the tailnet).

## Custom `service.machine` names on a tailnet — findings

**Goal:** names like `gizmo.genge`, `gizmo.forge` (same service, multiple machines), with trusted HTTPS and no per-device setup.

**What Tailscale gives you natively — and why none of it fits:**
- **MagicDNS** resolves machine names only (`genge`, `genge.angler-musical.ts.net`). No subdomains of machine names, and per [Tailscale's own docs](https://tailscale.com/kb/1054/dns): *"It's not possible to add arbitrary records to MagicDNS"* ([tracking issue](https://github.com/tailscale/tailscale/issues/1543)). So `gizmo.genge` never resolves on its own.
- **`tailscale serve --tailscale` / portless `--tailscale`** registers HTTPS on the *machine's* MagicDNS name (`https://genge.…`), one port per extra app (443, 8443, …). Has a known stale-registration leak ([portless #280](https://github.com/vercel-labs/portless/issues/280), fix in [#400](https://github.com/vercel-labs/portless/pull/400)). Machine-scoped, not service-scoped.
- **tsnsrv / tsnet-serve** joins the tailnet as a *new node per service* (`gizmo.<tailnet>.ts.net`) with automatic certs. Right shape family, but: the tailnet name is in the URL, and one node per name means multi-machine needs `gizmo-genge`, `gizmo-forge`, etc.
- **Tailcat** (new, Aug 2026) is a red herring — netcat over the Tailscale data plane with no control plane, no DNS, no TLS certs. Not a naming or serving tool.
- **Portless custom TLDs** (`--tld`, incl. multi-segment like `dev.example.com`) work with a domain you own, but its proxy only listens off-loopback in LAN mode, which is unsupported on Windows.
- **Tailscale certs are per-node, not per-name.** `tailscale cert` issues only for a node's own full MagicDNS name. A name merely ending in `.ts.net` (e.g. `gizmo.genge.ts.net`) gets nothing from anyone — Tailscale won't issue it, Let's Encrypt can't (no DNS control of `ts.net`).

**The shape `service.machine` requires your own DNS:**
- **Split DNS (restricted nameservers)** in Admin console → DNS, pointing suffixes (`genge`, `genge.ts.net`, `genge.<you>.com`…) at a DNS server you run on the tailnet (dnsmasq/CoreDNS — a few `address=/…/` lines). Every tailnet device including phones resolves them; no per-device setup.
- Suffix choice is free: `gizmo.genge.ts.net` is rename-proof (no tailnet name in it); `gizmo.genge.<own-domain>` additionally enables public CAs.

**TLS is the actual constraint, with exactly three options:**
1. **Plain HTTP** — transport still WireGuard-encrypted; browsers show "Not Secure"; no secure-context APIs.
2. **Private CA (mkcert)** — green lock, but install + trust on every device (including the iPhone profile dance).
3. **Own public domain + DNS-01 (e.g. Caddy + Cloudflare)** — green lock everywhere, zero per-device work. Public A records → `100.x` are safe (unroutable off-tailnet; names resolve publicly but only connect via tailnet). `proxied` must be off. Same API token serves both the A records and renewals.

**Bottom line:** `service.machine` with trusted HTTPS and no device toil = own domain + split-or-public DNS + an auto-renewing reverse proxy per machine. Everything Tailscale-native either puts the machine or the tailnet name first, or can't do multi-machine under one service name.
