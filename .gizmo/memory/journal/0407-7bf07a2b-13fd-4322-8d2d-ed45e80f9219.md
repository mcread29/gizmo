**What changed**

- **Snapshot carries the run state.** The `session.resume` response now includes `state`, read from Pi's own `isStreaming` flag at the moment of the read. The client applies it on every switch and resync, so the composer's Stop and Steer mode comes from the runtime rather than from the last event the page happened to hear.
- **Gap detection and quiet resync.** The server no longer renumbers events per socket, and project events now share the agent hub's sequence, so every connection sees one contiguous run of ids. The client tracks the last id it received. A skipped id, or a heartbeat naming a newer id than it has seen, triggers a resync: it re-reads the thread, swaps the messages in place, and replays anything that arrived during the read past the snapshot's cutoff. Nothing is cleared, no loading state is shown, scroll and focus are untouched. A reconnect onto the same thread now uses the same path instead of blanking the transcript.
- **Heartbeat.** The server sends a heartbeat every 15 seconds on each socket, carrying its newest event id. It is a plain message, not an event, so it renders nothing. The client arms a silence watch only after the first heartbeat, so servers or fakes that send none are never timed out. Three missed heartbeats close the socket, which runs the normal backoff reconnect and the in-place resync.
