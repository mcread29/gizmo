## What's built

**Protocol 25** — `registry.status` / `registry.install` / `registry.update` / `registry.remove`.

**Server (`registry-manager.ts`)** — the clone/build/link pipeline:
- **Install by git URL**: shallow-clone into `~/.pi/agent/extensions-src/<name>/`, run the repo's declared build (from its optional `gizmo.registry.json`: `{ extensionsDir, build }`), then sync every `extensions/<name>/pi-extension.ts` → `extensions/<name>.ts` and any sibling `<name>.web.js` → the loaded extensions dir. Records the commit in `installed.json`.
- **Update**: `git pull --ff-only` + rebuild + re-sync. **Remove**: deletes the loaded artifacts, keeps the clone.
- Per-extension build isolation: one broken extension logs and skips instead of blocking the registry.
- The old seeding is **retired** — no extensions ship inside Gizmo anymore; `pi-extensions/` in the repo is now purely the dev/publishing home, and `ask-user.web.js` still builds via `pnpm pi-extensions:build`.

**Settings → Extensions**: shows the clone home, an install-by-URL form, and each installed registry with its commit, synced extensions (marked "tool + UI" or "tool"), and Update/Remove buttons.

## To try it

1. Reload the tab, open **Settings → Extensions**.
2. Publish your first registry repo (e.g. push `pi-extensions/ask-user/` as `ask-user` with the `pi-extension.ts` layout), or for a local test: `git clone` any registry-shaped repo and paste its path as the URL — git clones local paths fine.
3. Install → the pair lands in `~/.pi/agent/extensions/` → **Reload runtime** → the tool works and Gizmo serves its `.web.js` UI (the sibling-bundle serving from earlier).

The invariants you set all hold: Gizmo ships no extensions, the registry is yours (plain git — no npm, no third-party index), the UI never travels without its tool, and Gizmo's only role is moving files per each repo's manifest and rendering whatever the UI declares.
