## Raw transcripts: yes, all of them

Checked every path that could lose one:

- **Gizmo** — grepped every `unlink`/`rm`/`truncate` in `apps/agent-server/src` and `packages/*/src`. The only session-file deletion was the one in `delete()`, now an archive move. Everything else touches the extension registry, tool policy, or temp files.
- **Pi** — zero hits for `unlinkSync`/`unlink(`/`rmSync`/`prune`/`maxSessions` in `session-manager.js`. Pi never deletes or rotates a session file.
- **Compaction doesn't shrink the file.** A `CompactionEntry` is *appended*; the summarized messages stay on disk and just stop being sent to the model. The JSONL is strictly append-only.
- **Fork writes a new file**, never mutates the source.
- **Pool eviction** disposes the in-memory runtime only.
- **Attachments** now move with the transcript.

So at the JSONL layer: complete.

## Journal segments: no — three gaps

**1. Abandoned branches are never journaled.** `journal-recorder.ts:92` calls `getBranch()`, which returns only the active path to the current leaf. Fork or `/tree` away from a line of work and that branch lives in the JSONL forever but produces no segment. This one actually matters for what you want — abandoned branches are disproportionately where rejected approaches live, which is exactly the "we tried X and dropped it" material the knowledge layer should capture. `getEntries()` returns the whole tree; the reason I didn't use it is that a tree doesn't linearize into a readable transcript without deciding how to render the branch points.

**2. Normalization is lossy** — tool output truncated, by design, now that the raw survives in `sessions/archived/`.

**3. Nothing is wired**, so today the count is zero.

## A bug I introduced

Fork copies **all** entries into a new file with a new session id, preserving the original entry ids (`session-manager.js:1250-1275`). My `lastEntryIdFor()` is keyed on session id, so on a forked session it returns `undefined`, `entriesSince()` falls through to "return everything", and **the entire inherited history gets re-journaled under the fork's id.** Duplicate segments covering the same conversation.

The fix is small and the preserved entry ids make it clean: track journaled entry ids per *project* rather than per session. That's also simpler than what's there now. Nothing is at risk yet since the recorder is unwired.

## What is genuinely unrecoverable

Sessions you deleted **before** this change — those were `unlink`ed and are gone. The archive only protects deletions from here on. And there's no backfill: existing sessions produce no journal segments until you run one.

Want me to fix the fork duplication and add backfill for existing transcripts? Both are contained, and I'd do the fork one regardless before anything gets wired.

## The fork bug

Replaced session-keyed lookup with `resumeAfter(entries)` (`journal-store.ts:111`): it collects every segment's `lastEntryId` **project-wide** and walks the branch backwards for the newest match. Since forking preserves entry ids while changing the session id, matching on entry ids means a fork resumes exactly where its parent left off instead of re-journaling everything it inherited. Test pins it directly.

Bounded residual: if you fork from a point *inside* an already-journaled segment, the entries between the fork point and that segment's end get recorded twice. Storing every entry id per index line would make it exact, but that bloats the index for a rare case — no gaps either way, which is the property that matters.

## Wiring — `src/pi-extensions/memory-journal.ts`

Four hooks:

| Hook | Records |
|---|---|
| `session_compact` | span up to `firstKeptEntryId` — ends exactly where context resumes |
| `session_before_tree` | the branch about to be abandoned |
| `turn_end` | tail past 96KB, crash insurance |
| `session_shutdown` | whatever's left |

`session_before_tree` also closes the abandoned-branch gap I flagged earlier — that's the only moment `getBranch()` still describes the branch you're leaving. Every handler is wrapped so a journaling failure logs and never touches the session. `GIZMO_MEMORY_JOURNAL=0` disables it.

Loaded via `journalExtensionPath()` prepended to `additionalExtensionPaths` (`pi-session-factory.ts:79`) — bundled rather than discovered, so memory is on by default rather than something you configure per project.
