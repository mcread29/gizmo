## user

wait so if other people want to use this registry they'll have to fully clone the project?

## assistant

**With the current implementation, yes** — because I made the Gizmo repo itself the first registry. That’s wrong for other users: they’d clone the entire application just to install a few extensions.

The intended setup should be a **separate, lightweight registry repo**, for example:

```text
gizmo-extension-registry/
├── gizmo.registry.json
├── package.json
├── pnpm-lock.yaml
├── build script
└── extensions/
    ├── ask-user/
    │   ├── pi-extension.ts
    │   └── src/web/
    ├── subagents/
    └── workflows/
```

Users clone that once into:

```text
~/.pi/agent/extensions-src/gizmo-registry/
```

Then Gizmo builds it and links selected extension pairs into `~/.pi/agent/extensions/`.

The current registry support already handles this layout. What needs changing is:

1. Move `ask-user` and the registry build tooling into a dedicated repo.
2. Remove `gizmo.registry.json` and extension source from the Gizmo app repo.
3. Point Gizmo’s default registry URL at the lightweight registry repo.
4. Keep the URL configurable for your own or third-party registries.

A sparse checkout of this repo could avoid downloading everything, but that’s needless complexity. A dedicated registry repo is cleaner, smaller, independently versioned, and matches the architecture you described.
