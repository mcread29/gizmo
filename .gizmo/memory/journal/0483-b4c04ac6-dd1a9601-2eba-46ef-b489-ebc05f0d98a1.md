**The bug, in one line:** `switchSession` early-returned when you clicked the thread that was already open. Viewing a workspace screen moves the selected workspace (and drops the transcript); returning to that thread re-derived neither, because the thread itself hadn't changed.

**The fix, in one line:**

```js
if (sessionId === store.sessionId && store.messages.length) return this.rebindSelection();
```

Rebind when the transcript survived; otherwise fall through and reload it.

**Verified on live:**
- workspace → thread, 30 cases across 5 timings: was 30/30 wrong, now **0/30**
- transcript returns intact (5 messages → 5, was → 0)
- plain sidebar switching still clean, 0/24
