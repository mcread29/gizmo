# Plan: timeout-free run + notify-on-done (`call` / `wait`)

Branch: `feature/call-and-wait-tool` off `origin/main` (`cedef7e`), clean.

## Goal

Let an agent start a long script **without a timeout**, keep working, and get the output delivered as a message when it settles — same UX as `subagent_spawn` / `workflow(background:true)`, but for Gizmo's one execution primitive (`run_script` → Bun `.ts`/`.js`, no shell).

Non-goals: general shell, pipes, `.sh`, stdin interaction, surviving server restart.

## What exists today (modeled on)

* `apps/agent-server/src/scripts/run-script*.ts`: `execFile('bun', ...)` with `timeout` (default 60s, max 600s), `maxBuffer` cap, `truncated` flag. Non-zero exit is a result, not a throw.
* `extensions/registry/extensions/workflows/pi-extension.ts`: `background:true` → return run-id immediately, `pi.sendUserMessage(text, {deliverAs:"followUp"})` on settle. Background survives `Esc`, aborted on `session_shutdown`. Progress via throttled `onUpdate`.
* `extensions/registry/extensions/subagents/pi-extension.ts` + `src/result-delivery.ts`: `spawn` returns now, `manager.onSettled` → `resultDelivery.defer(sub)`, flush via `pi.sendMessage({customType:"subagent-result"...}, {deliverAs:"followUp", triggerTurn:true})` on `isIdle()` / `agent_settled`. `subagent_wait(ids)` consumes deferred delivery so no double-post.
* `subagents/src/tool-call-timeout.ts`: 3-min guard wrapping child tools — new tool must opt out / not be wrapped.

## Proposed shape (recommend)

Family, not a flag — matches subagents, avoids breaking `run_script` semantics:

1. `call` — `spawn detached Bun script, return {callId} now`
   ```ts
   { script: string, args?: string[64], label?: string }
   → { callId: "call_xxxx", logPath, message: "runs without timeout; you'll get a follow-up, or use wait/check" }
   ```
2. `wait` — `block for ids`
   ```ts
   { ids: string[64], timeoutSeconds?: number }
   → per-id { ok, exitCode, stdout, stderr, truncated, timedOut:false, durationMs }
   // consumes deferred follow-up (like subagent_wait), abort keeps job running
   ```
3. `check` / `list` / `cancel` — peek, all-runs, kill. `check` uses `onUpdate` for tail.

Keep `run_script` unchanged for short blocking runs.

## Engine changes

* New `apps/agent-server/src/scripts/call-manager.ts` (per-process, keyed by workspace+session):
  * `spawn` not `execFile`: `child_process.spawn('bun',['run',abs,...args], {cwd, shell:false})`, **no `timeout`**, no stdin.
  * Keep `run_script` guards: `isPathWithin`, runnable exts, file exists, string args only, missing-bun message.
  * Stream stdout/stderr to file (`~/.pi/agent/calls/<callId>/` or workspace `.gizmo/calls/` — open question) + in-memory ring; clamp to 20k chars like today, `truncated:true`.
  * Heartbeat persist (`workflow.json` pattern, 5s) so `/calls` can tell live vs dead.
  * Registry: `Map<callId, {proc, startedAt, label, status}>`, max N concurrent (propose 4, same as subagents), `dispose()` kills on reload, `session_shutdown` aborts+settles.
  * Background survives parent-turn `abort`/`Esc` (own `AbortController`, like workflow `RunController(background? undefined : signal)`); `cancel` kills explicitly.
* Wire in `sessions/pi-session-factory.ts` alongside `createRunScriptTool`: `createCallTools({workspacePath})`.

## Notify path

* Immediate `tool.completed` = ack (`launched call_xxx`), **not** the result.
* On settle: `defer(callId)`; if session `isIdle()` send now else wait for `agent_settled` — copy `subagents` `deliverResult`/`flushResults`:
  ```ts
  pi.sendMessage({customType:"call-result", content: resultText, display:true, details:{id,title,status}}, {deliverAs:"followUp", triggerTurn:true})
  ```
* `wait(ids)` → `resultDelivery.consume(ids)` before returning (no doublepost).
* Headless (`!ctx.hasUI`): no follow-up UI — `wait`/`check` is the only path; `call` should warn in text.
* Progress: throttled `onUpdate({content, details: callCard})` + `ui.setStatus("calls", ...)` + optional declarative `/calls` dashboard (reuse `orchestration/activity-status`).

## Safety / limits

* No timeout, but: max output bytes, max concurrent, max age (sweep idle finished after e.g. 24h), kill on workspace removal.
* Tool-call guard: exclude `wait` from 3-min `tool-call-timeout` or set `wait` timeout = caller `timeoutSeconds`.
* Tests: `run-script` still capped; new: spawn→wait ok, non-zero reported, truncation, `cancel` kills, `wait` consumes follow-up, abort-`wait` leaves job running, shutdown disposes.

2. **Core `call`+notify (1d):** manager + `call` tool + deferred follow-up, unit tests.
3. ** `wait`/`check`/`list`/`cancel` (1d):** blocking wait with progress, consume logic, status indicator.
4. **Polish (0.5d):** docs (`docs/extensions.md` run_script section), promptGuidelines ("keep working; results arrive; only wait if blocked"), `/calls` view if cheap.
