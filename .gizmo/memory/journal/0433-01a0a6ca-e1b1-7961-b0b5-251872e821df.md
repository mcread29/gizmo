## Findings

### 1. High: branching a user entry creates an invalid branch

- `apps/app/src/lib/features/tree/SessionTreeScreen.svelte:81-84`
- `apps/app/src/lib/features/tree/SessionTreeScreen.svelte:190`
- `apps/app/src/lib/features/tree/SessionTreeActions.svelte:37-60`
- `apps/agent-server/src/sessions/session-operations.ts:137-140`

`Continue from here` and double-click always call `branchTo(entry.id)`. For a user entry, this makes the next prompt a child of the old user message, producing `user → user`.

Pi’s installed `AgentSession.navigateTree()` semantics instead move to the user entry’s parent and prefill the user text for editing. The existing `runEdited()` happens to implement this correctly at `SessionTreeScreen.svelte:94-98`, but the normal Continue path does not.

**Suggested change**

- Only offer “Continue from here” for non-user entries.
- Rename the user action to “Fork and edit”.
- Remove double-click branching, or make it follow the same entry-kind rules.
- Add tests for root and non-root user entries.

### 2. High: server branching bypasses Pi runtime state updates

- `apps/agent-server/src/sessions/session-operations.ts:128-141`

The server directly calls `manager.branch()` / `manager.resetLeaf()`. The installed Pi runtime’s `navigateTree()` also updates `agent.state.messages` and emits the tree-navigation lifecycle event.

The client updates `store.messages`, so the UI appears correct, but the next server prompt may still use the abandoned branch’s runtime context.

**Suggested change**

Expose a tree-navigation operation on `PiSessionLike` and delegate to Pi’s `navigateTree()` (or implement equivalent synchronization). Preserve the special root-user behavior and ensure the active runtime context is rebuilt before the next prompt.

**Tests**

- Branch to an earlier assistant entry, submit another prompt, and assert the runtime context excludes the abandoned branch.
- Branch from a user entry and assert the new prompt is a sibling, not a child.
- Test root-user re-run behavior.

### 3. High: fake branching deletes history instead of creating a branch

- `apps/app/src/lib/agent-client/fake-client/sessions.ts:80-109`

The fake client stores only a linear `messages` array. `branch()` slices it:

```ts
session.messages = session.messages.slice(0, index + 1);
```

This contradicts the real append-only tree and makes abandoned branches disappear. The existing `session-tree.test.ts` uses a handcrafted tree, so it never exercises the fake implementation.

**Suggested change**

Model fake sessions with:

- persistent all-entry storage,
- explicit `parentId`,
- a current `leafId`,
- branch navigation that only changes the leaf.

Add a `FakeAgentClient` test that:

1. creates two prompts,
2. branches to the first turn,
3. submits an alternative prompt,
4. verifies both old and new branches remain visible.

### 4. High: tree refresh revision misses completed streaming entries

- `apps/app/src/lib/features/tree/SessionTreeScreen.svelte:39-44`
- `apps/app/src/lib/agent-client/agent-event-reducer.ts:59-76`
- `apps/agent-server/src/sessions/session-transcript.ts:122-132`

`treeRevision` uses only `sessionId` and `messageCount`. The store increments `messageCount` on `message.started`, while the server tree may not contain the assistant entry until the response completes. If the tree is opened during streaming, it can remain stale after completion because no revision changes at completion.

The revision also ignores non-message tree entries such as model changes, compactions, and branch summaries.

**Suggested change**

Use an explicit tree revision/version from the server, or force a tree reload on message completion / relevant session events. Add an integration test that opens the tree mid-stream and verifies the completed assistant row appears without closing/reopening.

### 5. Medium: current leaf can disappear under the default filter

- `apps/app/src/lib/features/tree/session-tree.ts:47-55`
- `apps/app/src/lib/features/tree/SessionTreeScreen.svelte:66-68`

A tool-only assistant is represented as `kind: 'tool'` and excluded by the default filter. If it is the current `leafId`, the initial selection points to an entry that is not present in `rows`; `selected` becomes undefined and the action footer says “Select an entry”.

**Suggested change**

Either:

- always render the current leaf, even when filtered, or
- resolve selection to the nearest visible ancestor and explain that the exact leaf is hidden.

Add a test where `leafId` is a filtered-out tool entry.

### 6. Medium: errors can discard the user’s edited prompt

- `apps/app/src/lib/features/tree/SessionTreeScreen.svelte:92-99`

`editing` is cleared before `branchTo()` runs. If branching fails, the editor closes and the typed replacement prompt is lost.

**Suggested change**

Keep the edit state until branching succeeds. Add a pending state and retain the text on failure.

---

### 7. Medium: branch actions are not concurrency-safe

- `SessionTreeActions.svelte:37-60`
- `SessionTreeScreen.svelte:81-88`

Buttons are disabled only while streaming. Repeated clicks can issue multiple branch requests concurrently, and double-click provides another path to the same operation.

**Suggested change**

Add a `branching`/`forking` state, disable all tree actions while it is active, and ignore duplicate requests. Test with a fake client latency and repeated clicks.

---

### 8. Medium: server tree serialization drops valid Pi entry types

- `apps/agent-server/src/sessions/session-transcript.ts:152-203`

`treeEntry()` has no representation for `custom_message`, `custom`, `custom_message`-style extension entries, bash entries, or other valid session entries. The protocol even defines `kind: 'other'`, but this function never emits it.

This means the tree is not actually “every turn” for sessions containing extension-injected context or other persisted entries.

**Suggested change**

Map supported non-message entries to `kind: 'other'` with a useful summary/detail. Add serialization tests for custom messages, branch summaries, compactions, and model/thinking changes.

---

### 9. Low: malformed parent cycles can hang `treeRows`

- `apps/app/src/lib/features/tree/session-tree.ts:116-122`

`activePath()` has cycle protection, but `visibleParent()` does not. A self-parent or cyclic entry can loop forever. Pi’s own tree handling explicitly treats self-parent entries as roots.

**Suggested change**

Track visited IDs in `visibleParent()` and fall back to `null` on cycles. Add a malformed-tree test.

---

### 10. CSS/responsive risks

- `apps/app/src/styles/shell-parts/resize-and-navigation.css:94-165`
- `apps/app/src/styles/shell-parts/session-tree.css:27-53`

The tree screen lacks the explicit `min-height: 0` / `min-width: 0` constraints used by the settings layout. Long trees may overflow or clip depending on grid sizing.

The action footer has no wrapping behavior, so the buttons can overflow narrow windows. The editor is absolutely positioned over the footer and has no max-height or overflow handling.

**Suggested change**

Add tree-specific scroll sizing constraints, responsive footer wrapping, and bounded editor height/scrolling. Add a narrow viewport visual/integration test.

## Recommended interaction model

1. **Single click selects; no implicit branching.**
2. User entries show **“Fork and edit”** with the original prompt prefilled.
3. Assistant/tool/other entries show **“Fork and continue”** with an empty composer.
4. Branch only when the user submits the new prompt, or keep the tree action visibly pending until the prompt is submitted.
5. Keep the old branch immutable and visible.
6. Use one server-side navigation operation that updates both the session manager leaf and the live Pi runtime context.
7. Keep the editor open and preserve text if branching or prompting fails.
