## Assessment

The move is directionally correct, but not complete or currently safe.

### Settings

Current work already:

- Removes top-level `compilePlayModePolicy` from `AppSettings`.
- Adds `extensionSettings: Record<string, Record<string, unknown>>`.
- Migrates legacy `compilePlayModePolicy` into
  `extensionSettings.unity.compilePlayModePolicy`.
- Gives Unity generic `extensionSetting`/`setExtensionSetting` access.

Two issues remain:

1. **Runtime blocker:**  
   `WorkspaceLayout.settings` calls:

   ```ts
   structuredClone(this.extensionSettings)
   ```

   `extensionSettings` is a deep `$state` proxy, so this throws `DataCloneError`. The app integration suite currently fails during `App.svelte` initialization.

2. **The extension contract still exposes `WorkspaceLayout`:**  
   `GizmoWebExtension.settings` and `dialog` remain coupled to the whole app layout, and Unity must pass `"unity"` into every settings call. This is generic storage internally, but not a clean generic extension contract.

### Persistence choice

Keep extension preferences inside the existing device-level `gizmo.settings.v1` envelope. This is preferable to:

- direct extension `localStorage`, which duplicates error handling and breaks global reset/migration;
- project configuration, which would incorrectly commit a personal Play Mode preference to the workspace;
- server persistence, which adds protocol/file work for a browser/device preference.

Do not bump the storage key. Reading the legacy field and writing only the new nested field provides an automatic one-save migration.

## Bundle lifecycle issue

`build-web-extension.ts` correctly embeds extracted CSS, but its generated prelude only inserts a style when none already exists. Therefore `/reload` cannot update CSS for an already-loaded extension, and removed or rejected extensions can leave styles behind.

Bounded fix:

1. **Registry `scripts/build-web-extension.ts`**
   - Upsert the marked style element.
   - Always replace `textContent`.
   - Remove the previous element when a rebuilt extension emits no CSS.

2. **App `extensions/runtime/install.ts`**
   - After loading/validation, remove
     `style[data-gizmo-extension-style]` entries whose IDs are not in the successfully loaded extension set.

3. Re-run registry `pnpm build`; current `activity.web.js` and `git.web.js` are stale and do not yet contain style preludes, while `unity.web.js` contains only its earlier console CSS.
