Fixed and verified on live.

**The bug:** the loader looks up one name in every bundle — `gizmoWebExtension` — but Unity's web entry exported the object as `unityWebExtension`. So its bundle downloaded, evaluated, and was then rejected: *"bundle does not export a gizmoWebExtension object."*

**The fix** — one line in `~/.gizmo/registries/gizmo-registry/extensions/unity/src/web/index.ts`:

```ts
export { unityWebExtension as gizmoWebExtension } from "./gizmo-extension";
```

Then I rebuilt the bundle with the repo's own builder (`packages/extension-build` CLI) into `~/.pi/agent/extension-web/unity.web.js`. It now ends `export { MA as gizmoWebExtension }`, matching ollama's.

**Verified:**

| project | inspector tabs | Unity |
|---|---|---|
| cronkis (enables `unity`) | Git, Ollama, **Unity**, Codex, Subagents, Workflows | ✓ |
| jev-melee (doesn't) | Git, Ollama, Codex, Subagents, Workflows | — |

Unity's stylesheet loads, the panel renders its Runtime State UI, and the console is clean — no extension errors at all now.

**One thing it surfaced,** which you should decide on. The Unity panel says:

> No project service is registered for extension "unity"

The *UI* is there, but the server-side project service isn't. `registeredExtensions()` is built from `~/.pi/agent/extensions/`, and Unity lives in `extensions-disabled/` — so although cronkis's config enables it (and my earlier fix now gets its code into the session's extension paths), the Gizmo server extension itself is never registered. The web half honors the project override; the server-extension registry still doesn't.

Two ways forward:
- **Move `unity` back to `~/.pi/agent/extensions/`** (re-enable it globally). No code change, everything works immediately — sensible if you disabled it for TUI reasons rather than because it's broken.
- **Make the server extension registry project-aware**, so a workspace override can register an extension that's globally off. Bigger change; it's the last layer of the same asymmetry I fixed in the other three.

I kept backups of both files I touched (`/tmp/unity-index.bak`, `/tmp/unity.web.js.bak`). Note the source edit is in the **registry repo**, not gizmo — it's uncommitted there.
