## The key insight about Pi's context model

Pi gives you three distinct injection points, and a good memory system uses all three for different reasons:

| Hook | Fires | Gets | Persisted? |
|---|---|---|---|
| `before_agent_start` | once per user prompt | `prompt`, `systemPrompt`, `systemPromptOptions` | yes — returns a `message` stored in the session |
| `context` | **before every LLM call** | deep copy of `messages`, safe to mutate | no — ephemeral, per-call |
| `session_before_compact` | on threshold/overflow/`/compact` | `preparation`, can return a custom `summary` | yes — becomes the `CompactionEntry` |

`context` is the real lever for "custom context construction" — it's the only hook that runs on *every* call and lets you both inject and prune non-destructively. `before_agent_start` is for things that should live in the transcript permanently.

## Architecture

Memory as **files on disk**, not a vector DB. One fact per file under `<workspace>/.gizmo/memory/`, plus a `MEMORY.md` index of one-line pointers. This gives you: git-diffable, user-editable, no embedding infra, and — critically — the index is cheap enough (a few hundred tokens) to sit in context *always*, with full bodies loaded on demand.

```
.gizmo/memory/
  MEMORY.md              ← index, always in context
  auth-uses-clerk.md     ← body, loaded on retrieval
  prefers-tabs.md
```

### Write path — tools

Register `memory_write` / `memory_delete` via `pi.registerTool()`. Use `promptSnippet` and `promptGuidelines` so the tool self-documents into the system prompt's `Available tools` and `Guidelines` sections rather than you hand-rolling prompt text:

```ts
pi.registerTool({
  name: "memory_write",
  promptSnippet: "Persist a durable fact about the user or project",
  promptGuidelines: [
    "Use memory_write when you learn something that will still matter in a future session.",
  ],
  parameters: Type.Object({ name: Type.String(), type: StringEnum([...]), body: Type.String() }),
  async execute(id, params, signal, onUpdate, ctx) { /* write file + update index */ },
});
```

### Read path — `context`, not `before_agent_start`

```ts
pi.on("context", async (event, ctx) => {
  const injected = { role: "user", content: renderMemoryBlock(await recall(event.messages)) };
  return { messages: [event.messages[0], injected, ...event.messages.slice(1)] };
});
```

Two things this buys you that `before_agent_start` can't:

1. **Recall re-runs mid-turn.** The agent reads three files, and the next LLM call can now surface a memory that wasn't relevant at prompt time.
2. **Injection stays out of the session log.** Memory text never accumulates in the transcript, so it never gets summarized into a compaction and duplicated.

The cost is cache invalidation — inserting after the system prompt busts the prompt cache on every change. Mitigate by keeping the block **stable within a turn** (compute recall once per `turn_start`, reuse it across the turn's calls) and placing it at a fixed position.

Use `before_agent_start` only for the always-on part — append the `MEMORY.md` index to `event.systemPrompt`:

```ts
return { systemPrompt: event.systemPrompt + "\n\n" + memoryIndex };
```

### Retrieval

Start with the index-in-prompt + explicit `memory_read` tool, and let the model do retrieval. It's dramatically better than naive keyword matching and costs one round-trip. Add a cheap lexical prefilter in `context` (score index lines against the last user message + recently-touched file paths, inject top-N bodies) only if you measure the model failing to call `memory_read`. Skip embeddings until you have >200 memories.

### Compaction is the harvest point

This is the part most memory systems miss. Compaction is exactly the moment where "what mattered in the last 100k tokens" is being computed — reuse it:

```ts
pi.on("session_before_compact", async (event, ctx) => {
  // let Pi generate its summary, then mine it for durable facts
});
pi.on("session_compact", async (event, ctx) => {
  await harvestMemories(event.compactionEntry.summary);
});
```

Note gizmo already maps its own `CompactionPolicy` onto Pi's `reserveTokens`/`keepRecentTokens` at `apps/agent-server/src/sessions/pi-session-factory.ts:163`. If you want memory-aware compaction you'd extend that policy rather than fight it. Also: `CompactionEntry.details` is `T = unknown` and extension-writable — you can stash `{ memoriesWritten: [...] }` there so a fork or `/tree` navigation carries the provenance.

## Wiring into gizmo

There's a structural gap to close first. `GizmoServerExtension` (`packages/extensions/src/extension.ts:16`) only exposes `systemPrompt`, `createTools`, `list`/`invoke`, and `createProjectService` — **no `pi.on` access**. Every hook above requires a real Pi extension.

Note `apps/agent-server/src/pi-extensions/` exists and is empty — that looks like the intended home. Two pieces:

1. **A Pi extension file** in `src/pi-extensions/memory.ts`, loaded by adding it to `additionalExtensionPaths` in `resourceLoaderOptions` (`pi-session-factory.ts:75`). This owns `context`, `before_agent_start`, `session_before_compact`, and `registerTool`.
2. **A `GizmoServerExtension`** wrapping the same store, so the memory list gets a UI — `list()`/`invoke()` give you browse/edit/delete in the sidebar, matching the extension-owned workspace UI pattern from `0723f28`.

Both point at one `MemoryStore` class in `packages/extensions/src/` so there's a single implementation of read/write/index.

## Phasing

1. `MemoryStore` + `memory_write`/`memory_read` tools + index appended in `before_agent_start`. Ship this alone — it's most of the value.
2. `context` hook for dynamic recall and turn-scoped caching.
3. Compaction harvest.
4. Gizmo UI via `list`/`invoke`.

## Two things that will bite you

- **Cache thrash.** Anything injected before the last cache breakpoint invalidates it. Measure token cost before/after; if it regresses, move injection to the *end* of the message list instead of after the system prompt.
- **`context` gets a deep copy.** Mutating `event.messages` in place does nothing — you must `return { messages }`. Easy to write a hook that silently no-ops.
