## Recommendation

Treat this as an internal vocabulary refactor with explicit protocol adapters:

- `activeDomains` → `enabledExtensionIds`
- singular legacy `domainId` → canonical `integrations`
- runtime aggregate `activeDomains` → `activeExtensions`
- project detection’s `domains` should remain a wire field, but map internally to `availableExtensions`

Do **not** bump `protocolVersion` or emit new parallel wire fields in protocol v25. Schemas use `additionalProperties: false`; sending both old and new fields would break existing clients.

1. Introduce the canonical schema name:

```ts

```

Update internal protocol references and `WorkspaceIntegration` to use `workspaceIntegrationSchema`. Keeping the alias avoids TypeScript API breakage.

2. Reuse `workspaceIntegrationSchema` in both `sessionOptionsSchema` and `agentSessionSummarySchema` instead of duplicating the summary object schema.

3. Annotate both `domainId` properties:

```ts
/** @deprecated Protocol compatibility only. Use integrations. */
domainId: Type.Optional(...)
```

4. Add a single compatibility normalizer:

```ts
export function sessionIntegrations(value: {
	integrations?: readonly WorkspaceIntegration[];
	domainId?: string;
}) {
	if (value.integrations !== undefined) return value.integrations;
	if (value.domainId === undefined) return undefined;
	return value.domainId === 'generic'
		? []
		: [{ id: value.domainId, root: '.' }];
}
```

Required semantics:

- Explicit `integrations: []` wins over `domainId`.
- `domainId: 'generic'` means explicit no integrations.
- No field returns `undefined`, allowing the server to use workspace defaults.
