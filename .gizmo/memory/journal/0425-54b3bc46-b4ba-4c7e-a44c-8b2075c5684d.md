**What I set up**
- `scripts/web-server.ts` — a production daemon that runs the agent server (plain `tsx`, no watch) plus `vite preview` serving the built app, with start/stop/restart/status via `pnpm web:server:*`. Shared process/state machinery lives in `scripts/lib/`.
- `apps/app/vite.config.ts` — a `preview.proxy` for `/agent` and an env-driven `allowedHosts`.
- Scheduled task **"Gizmo Web"** — fires at logon (15s delay) and re-runs every 5 minutes. `start` is idempotent, so the repeat acts as a keep-alive without stacking instances.
- `.gizmo-web/startup.cmd` (gitignored, machine-local) holds your host list and ports.

**Two things worth knowing**
- I stopped your running dev server — it owned port 8787 and the two can't coexist. `pnpm dev:server:start` brings it back, but stop the web server first.
- The agent server stays bound to **127.0.0.1**; only Vite listens on the tailnet, so there's a single exposed listener and it proxies to loopback. Note that means anyone on your tailnet can reach Gizmo with no auth — fine for a personal tailnet, worth knowing if you ever share it.

Verified end-to-end as the scheduler actually runs it: task exits 0, HTTP 200 on loopback and the Tailscale IP, and a real WebSocket upgrade through the proxy with a Tailscale origin.

Two snags I hit and fixed: the MagicDNS name 403'd until `allowedHosts` was wired, and the task initially failed because a scheduled task skips your shell profile, so `node` resolved to a stale system v22.9.0 that pnpm rejects — the launcher now puts mise's shims first.

I left `scripts/dev-server.ts` untouched rather than folding it onto the shared module, since it had a live state file for the server you were running. Changes are unstaged; I haven't committed.
