## Fix 1 — a message the run never delivered comes back

**Server.** `SessionRuntimePool.activate` now watches for `agent_settled` and, if anything is still queued, drains it with Pi's `clearQueue()` and emits `session.unsent`. Hooking settlement rather than `abort()` is deliberate: your Slapdash message wasn't stranded by an abort you made, it was stranded by the provider dropping the run. A settled session has no run left to deliver anything, so whatever is still queued is stranded by definition. Extracted to `apps/agent-server/src/sessions/queue-recovery.ts:16`.

**Client.** `restoreUnsent` (`apps/app/src/lib/features/conversation/unsent.ts`) puts the text back at the top of the composer draft, ahead of anything already typed, and a warning toast says why it's there: *"That message was never delivered, so it is back in the composer."*

## Fix 2 — an interrupted turn says so

`interrupted` now rides on `ConversationMessage` and on `message.completed`, set from `stopReason` of `aborted`/`error`. Two paths, because a turn can die live or be read back from the file later:

- `pi-event-translator.ts` flags it on the live `message.completed`
- `sessionTranscript` flags it when rebuilding from the session file

`MessageGroup.svelte` renders a quiet italic *"Response interrupted"* line — muted, not an error banner, since a stopped turn is a fact about the response rather than a failure of the app.

## Protocol

Bumped **26 → 27**. A new event type is a breaking change for a strict-parsing client, and the handshake should refuse an old one rather than let it throw on an event it can't parse. Two tests had `protocolVersion: 26` hardcoded; they now import the constant so the next bump doesn't break them.

## What changed in the toolbar

`ComposerToolbar.svelte` moved the danger "Stop response" button out of the `composer-send` cluster to the far left, beside Attach. The send cluster is pinned right by `margin-left: auto`, so Stop is now the maximum distance from the button you actually aim for. Stop is still there while streaming — just not where a slip lands on it.

The integration test now asserts the arrangement structurally rather than just checking both buttons exist:

```ts
expect(document.querySelector('[data-ui="composer-send"]')).toContainElement(steerButton);
expect(document.querySelector('[data-ui="composer-send"]')).not.toContainElement(stopButton);
```

So a future refactor that drifts Stop back into the send position fails the suite instead of quietly re-arming the hazard.
