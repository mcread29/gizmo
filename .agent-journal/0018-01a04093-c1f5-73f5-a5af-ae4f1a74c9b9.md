## What pstack is

[pstack](https://github.com/cursor/plugins/tree/main/pstack) is Lauren Tan’s public Cursor plugin for rigorous AI-assisted engineering. It is a skill collection and workflow router rather than a standalone skills manager. The canonical source is `cursor/plugins`; other repositories are mirrors.

The current manifest identifies version `0.14.3`, MIT licensing, and two component roots:

```json
{
  "skills": "./skills/",
  "agents": "./agents/"
}
```

Source: [plugin.json](https://github.com/cursor/plugins/blob/main/pstack/.cursor-plugin/plugin.json)

## Notable UX and features

- **Two-step onboarding.** `/add-plugin pstack`, then `/setup-pstack`. The setup skill detects available models, displays role assignments, validates selections, and writes an idempotent override file.  
  [Setup guide](https://github.com/cursor/plugins/blob/main/pstack/docs/guide/01-setup.md) · [setup-pstack skill](https://github.com/cursor/plugins/blob/main/pstack/skills/setup-pstack/SKILL.md)

- **One primary entry point.** `/poteto-mode` classifies a request into one of 22 playbooks and invokes narrower skills when needed. Users do not need to understand the full catalog first.  
  [README](https://github.com/cursor/plugins/tree/main/pstack#readme) · [poteto-mode](https://github.com/cursor/plugins/blob/main/pstack/skills/poteto-mode/SKILL.md)

- **Sticky modes.** `poteto-mode` remains active across turns, has an input badge configured with `icon` and `color`, and supports explicit opt-out.

- **Visible execution contract.** A selected playbook becomes a todo list. Skipped steps remain visible with `skip: <reason>`, making routing decisions auditable.

- **Role-based model routing.** Models are assigned by capability such as code, judgment, exploration, or review. Lists control review-panel fan-out. `inherit-parent` and `auto` provide graceful fallback.

- **Composable skill taxonomy.** The collection distinguishes router/mode skills, workflow skills, principle leaves, generators, reviewers, and subagents. This is more useful than presenting every skill as an undifferentiated command.

- **Progressive personalization.** `/automate-me` mines workspace-local transcripts, asks a small set of structured questions, and creates or updates a personal `<handle>-mode` skill.  
  [automate-me](https://github.com/cursor/plugins/blob/main/pstack/skills/automate-me/SKILL.md)

- **Project-local verification.** Setup can offer a generated `verify-<app>` skill containing launch, doctor, drive, evidence, cleanup, and feature-map instructions. It must execute successfully before handoff.  
  [create-verification-skill](https://github.com/cursor/plugins/blob/main/pstack/skills/create-verification-skill/SKILL.md)

- **Explicit dependencies.** The README calls out capabilities supplied by another plugin, `cursor-team-kit`. A manager should surface missing or optional dependencies rather than letting references fail at runtime.

## File conventions

Typical pstack layout:

```text
pstack/
├── .cursor-plugin/plugin.json
├── README.md
├── skills/
│   ├── setup-pstack/SKILL.md
│   ├── poteto-mode/
│   │   ├── SKILL.md
│   │   ├── playbooks/*.md
│   │   ├── references/*
│   │   └── scripts/*
│   └── principle-*/SKILL.md
├── agents/*.md
├── docs/guide/*.md
└── automations/*
```

Runtime/generated locations include:

- `~/.cursor/rules/pstack-models.mdc` for user-level model overrides.
- `.cursor/skills/verify-<app>/` for project verification skills.
- `.cursor/skills/<handle>/<handle>-mode/` or `~/.cursor/skills/...` for personalized modes.

The broader Agent Skills convention is one directory per skill with a required `SKILL.md`, plus optional `scripts/`, `references/`, and `assets/`. Metadata is loaded first; full instructions and resources are loaded progressively.  
[Agent Skills specification](https://agentskills.io/specification)

Cursor additionally supports:

- Project and user scopes.
- Compatibility directories for Cursor, Agent Skills, Claude, and Codex.
- Nested, directory-scoped skills.
- `paths`, `disable-model-invocation`, `icon`, and `color`.
- Manual `/skill-name` invocation and session-long Custom Modes.
- A Customize UI organized by scope and invocation behavior.

Source: [Cursor Agent Skills documentation](https://cursor.com/docs/skills)

## Concise product inspiration

For an AI skills manager, the strongest ideas to borrow are:

1. **Lead with “Install → Configure → Run one task,” not a large catalog.**
2. **Provide a router skill that chooses specialist workflows automatically.**
3. **Show scope, provenance, invocation policy, dependencies, and portability for every skill.**
4. **Represent skill relationships visually:** router → playbook → specialist → principle → script.
5. **Offer a role/model matrix with availability validation and inherited defaults.**
6. **Make setup and updates idempotent, previewable, and reversible.**
7. **Support project-local, user-global, plugin-provided, and nested/package scopes.**
8. **Expose execution evidence, skipped steps, and verification status in the UI.**
9. **Treat scripts and reference files as first-class skill resources, loaded on demand.**
10. **Validate against the open standard.** Notably, pstack’s `Poteto Mode` frontmatter uses a display-style name, while the portable Agent Skills specification requires lowercase hyphenated names matching the directory. A manager should flag such compatibility differences without necessarily rejecting host-specific extensions.
