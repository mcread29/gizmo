## Task 1 — `journal_search` tool

The agent must be able to search its own project history.

- Lexical search across segment bodies (no embeddings, no SQLite — 9 MB greps in milliseconds).
- Returns ranked excerpts, each labelled with its segment id, plus enough surrounding lines to be
  readable. Cap total returned bytes so a broad query can't blow up context.
- Add a companion read path so the agent can pull a full segment by id after a search hit.
- Register via `pi.registerTool({...})` inside `memory-journal.ts`. Use `defineTool`-style
  parameters with `typebox` (see `apps/agent-server/src/scripts/run-script-tool.ts` for the
  house pattern).

### Exposure — do not skip this

Registering a tool is not the same as the model knowing it exists. Set `promptSnippet` and
`promptGuidelines` (guidelines must name the tool explicitly — "Use journal_search when…", never
"this tool"). Then **verify the tool actually reaches the system prompt**, because there is a
known trap:

`pi-session-factory.ts` sets `systemPromptOverride` whenever an active Gizmo extension supplies a
prompt or the user has a saved custom prompt. That override replaces Pi's built prompt *wholesale*,
which discards `toolSnippets`/`promptGuidelines`. So exposure works in the default case and
silently breaks in the override case.

Confirm both paths. If the override path drops the snippet, add a `before_agent_start` handler that
appends a short tool-availability line to `event.systemPrompt` (which chains correctly), and test it.

## Pitfalls hit while building this layer

- **Don't put Windows paths in bash heredocs.** Backslashes collapse even in quoted heredocs,
  producing drive-relative paths and silent zero-result runs. Pass paths via `process.cwd()` or argv.
- **Prettier reflows unions and call signatures**, which breaks blind string-replace edits. Assert
  every replacement, or use the Edit tool.
- **`getBranch()` vs `getEntries()`**: the latter includes retried/abandoned siblings and imports as
  duplicated prose. The journal uses `getBranch()` deliberately.
- **Verify tool loading through the real path.** `resourceLoader.loadExtensionFactories()` is *not*
  the load path and returns empty; the real result lands in `extensionsResult` after `load()`.

4. tsc clean, full suite green, new tests cover chunk boundaries and search ranking/caps.

## assistant

Done. Everything in the definition of done is met, with one caveat on the 40 KB target explained below.

**What I built**

- `journal_search` and `journal_read` tools, defined in `apps/agent-server/src/memory/journal-tools.ts` with typebox parameters and registered from the memory-journal extension. Search is a linear lexical scan in `journal-search.ts`: lines are scored by distinct terms matched, widened into merged context windows, ranked, and capped per segment, by hit count, and by total bytes. Read returns a full segment by id and pages by line if one is oversized.
- A `before_agent_start` handler in the extension appends one tool-availability line to the system prompt when it does not already mention the tools. This is what covers the override path.
- Chunking in `journal-chunk.ts`: spans are cut at user-message boundaries at about 40 KB, and a single turn that alone exceeds the budget is cut in front of assistant messages, so a tool call and its result always stay together. `JournalStore.append` now returns one meta per chunk, all indexed, so the last chunk's entry id is the resume point.
- The backfill CLI now defaults the workspace to pnpm's `INIT_CWD`, so running it from the repo root targets the repo.
