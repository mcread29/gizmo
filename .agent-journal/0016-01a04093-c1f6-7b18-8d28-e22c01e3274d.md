## Ben Davis’ public Pi setup

### Primary sources

- **Setup repository:** https://github.com/davis7dotsh/my-pi-setup  
  Opinionated `~/.pi/agent` configuration. Ben explicitly says it changes frequently and is better treated as a demonstration than copied wholesale.
- **Setup instructions:** https://github.com/davis7dotsh/my-pi-setup/blob/main/SETUP.md
- **Main walkthrough — “How I Turned Pi Into the Ultimate Coding Agent”:**  
  https://www.youtube.com/watch?v=6xXjHM3V1zM
- **Later cross-harness follow-up — Pi + Codex + Claude Code:**  
  https://www.youtube.com/watch?v=5Qu2SkSQeBU
- **Ben’s site/profile hub:** https://www.davis7.sh/

### How it is managed

- The repository is intended to live directly at `~/.pi/agent`.
- Conventional top-level directories provide automatic discovery:
  - [`extensions/`](https://github.com/davis7dotsh/my-pi-setup/tree/main/extensions) — TypeScript functionality and TUI integrations.
  - [`skills/`](https://github.com/davis7dotsh/my-pi-setup/tree/main/skills) — concise operational guidance teaching the model when and how to use capabilities.
  - [`themes/`](https://github.com/davis7dotsh/my-pi-setup/tree/main/themes) — GitHub Dark Default.
- **Capability/policy pairing:** complex extensions such as background terminals and subagents have matching `SKILL.md` files. The extension implements tools; the skill establishes usage policy.
- Current skills are deliberately sparse:  
  [`background-terminals`](https://github.com/davis7dotsh/my-pi-setup/blob/main/skills/background-terminals/SKILL.md) and [`subagents`](https://github.com/davis7dotsh/my-pi-setup/blob/main/skills/subagents/SKILL.md).
- Extensions are modular directories, often with their own tests and package metadata. Root scripts provide TypeScript checking, formatting, and tests:  
  https://github.com/davis7dotsh/my-pi-setup/blob/main/package.json
- Runtime state, credentials, model configuration, summaries config, sessions, and workflow artifacts are excluded from Git:  
  https://github.com/davis7dotsh/my-pi-setup/blob/main/.gitignore

### Notable UX patterns

- **Ambient dashboard instead of verbose status messages:** footer shows cwd, model, thinking level, context usage/window, cost, token speed, branch, changed-file count, PR, and extension activity.  
  https://github.com/davis7dotsh/my-pi-setup/blob/main/extensions/ui-customization/index.ts
- **Async by default:** background terminals and subagents return immediately, notify on completion, and expose nonblocking status tools.
- **Interactive control planes:** `/ps`, `/subagents`, and `/workflows` provide inspection, cancellation, live output, and—in the subagent case—interactive takeover.
- **Side-channel questions:** `/btw` starts a one-off subagent while the primary agent continues working.
- **Unified multi-harness delegation:** one subagent interface routes work to Pi, Claude Code, or Codex, with shared reasoning-effort controls and a concurrency cap.  
  https://github.com/davis7dotsh/my-pi-setup/tree/main/extensions/subagents
- **Progressive disclosure:** compact result previews expand with `Ctrl+O`; changed files open in a two-pane, keyboard-driven diff overlay.
- **Structured clarification:** `ask_user` presents 2–5 choices, always adds free-form input, permits dismissal, and enforces one question at a time.
- **End-of-run closure:** automatic “Run recap” cards summarize work and prominently show **Next:**.
- **Agent-authored orchestration:** workflows use a restricted inline-JavaScript DSL with named phases, parallel agents, structured outputs, dashboards, and persisted artifacts.

### Best inspiration to borrow

1. **Separate implementation from behavioral guidance:** extension = capability; skill = operating policy.
2. **Make concurrency visible but nonintrusive:** launch work asynchronously, surface compact activity counts, and deliver results automatically.
3. **Provide human escape hatches:** inspect, cancel, expand, or take over every autonomous process.
4. **Treat the footer as operational telemetry:** show context, cost, speed, Git state, and worker status continuously.
5. **Use progressive disclosure:** summaries first, full transcripts/logs/diffs on demand.
6. **Keep private state outside the shareable setup:** publish reusable behavior while ignoring credentials, sessions, and machine-specific model settings.
7. **Adopt selectively:** the repository has no detected license and explicitly discourages hard copying; use patterns as inspiration or request permission before redistributing code verbatim.
