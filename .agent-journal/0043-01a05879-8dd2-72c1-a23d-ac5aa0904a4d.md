# Main findings

## 1. `AgentStore` is the primary architectural bottleneck

### Mixed responsibilities

`apps/app/src/lib/agent-client/AgentStore.svelte.ts` currently owns:

- WebSocket connection and reconnect backoff
- Subscription lifecycle
- Session catalog, creation, switching, deletion, branching and renaming
- Transcript state and replay buffering
- Model/thinking selection
- Composer commands
- Project discovery, selection, status and opening
- Runtime web-extension installation
- Project-extension activation/invocation
- Resources, skills and Pi/Gizmo extension configuration
- Registry operations
- Tool policy
- Git status and commits
- Attachments and confirmations
- Error projection for every domain

The component tree consequently depends on one very broad mutable object. `AgentClient.ts` mirrors this with a 40+ method interface.

### Recommended boundary

Keep `AgentStore` temporarily as a compatibility façade, but delegate to reactive capability stores:

```text
apps/app/src/lib/agent-client/
  AgentStore.svelte.ts
  connection/
    ConnectionStore.svelte.ts
  sessions/
    SessionStore.svelte.ts
    session-selection.ts
    replay-buffer.ts
  workspaces/
    WorkspaceStore.svelte.ts
  resources/
    ResourceStore.svelte.ts
    ToolPolicyStore.svelte.ts
    RegistryStore.svelte.ts
  extensions/
    ProjectExtensionStore.svelte.ts
  git/
    GitStore.svelte.ts
```

Split `AgentClient` into capability interfaces such as `SessionClient`, `WorkspaceClient`, `ResourceClient`, and `ExtensionClient`, then compose them into the public `AgentClient`.

### Risks

- `switchSession` has important stale-request and event-replay guarantees.
- Workspace and session selection must continue changing atomically.
- Deeply reactive arrays/objects currently depend on Svelte proxy behavior.
- `agent-event-reducer.ts` mutates an `AgentEventState` structural interface; preserve this as a pure, independently tested boundary.
- Do not expose partially migrated child stores directly until their lifecycle and error semantics are stable.

   - `tests/**/*.ts`

   - **Node:** pure unit and build-script tests

7. Move the test-only Svelte hosts out of `src` so they are not part of the production source surface.

# Prioritized implementation phases

## Phase 0 — Characterization and test isolation

1. Create the `tests/` layout.
2. Split `App.test.ts` by shell, workspace, settings, composer, extension UI and accessibility.
3. Split `AgentStore.test.ts` by connection, sessions, workspaces and resources.
4. Move test-only Svelte hosts.
5. Introduce Node/jsdom Vitest projects and aliases.
6. Add direct tests for command-path parsing, message-row splitting, settings sections, UI primitives, highlighting and sanitization.

This phase should precede structural changes.

## Phase 1 — Establish package ownership

1. Remove or formally deprecate:
   - `packages/design/src/Button.svelte`
   - `packages/design/src/ConfirmDialog.svelte`
   - `packages/design/src/SelectField.svelte`
   - `packages/design/src/components.ts`
2. Move reusable app primitives into `packages/ui/src`.
3. Give `packages/ui` an explicit style/design dependency and supported CSS export.
4. Replace the direct CSS source import in `apps/app/src/main.ts`.
5. Add package-level check/test scripts.

## Phase 2 — Split client and state domains

1. Extract the WebSocket request engine.
2. Split `AgentClient` by capability.
3. Break up `FakeAgentClient` and make fixtures instance-local.
4. Introduce connection/session/workspace/resource sub-stores behind the existing `AgentStore` façade.
5. Preserve replay-buffer and stale-selection tests at each step.

## Phase 3 — Decompose feature screens

Recommended order:

1. `WorkspaceConfigurePanel.svelte`
2. `CommandPalette.svelte`
3. `Composer.svelte`
4. `MessageList.svelte`
5. `PiExtensionUiStore.svelte.ts`
6. `AgentSettings.svelte`
7. `SessionTreeScreen.svelte`
8. `App.svelte`

This order extracts reusable settings and state controllers before simplifying the shell.

## Phase 4 — CSS ownership and cleanup

1. Split `packages/design/src/components.css` by primitive.
2. Split `settings.css`, `dialogs.css`, `shell.css`, `composer.css`, and `inspector.css`.
3. Document runtime-extension style contracts.
4. Move extension-specific styles into extension bundles.
5. Delete selectors only after static and runtime usage is characterized.
6. Minimize contextual overrides of shared `button`, `tabs`, `select`, and skeleton primitives.

## Phase 5 — Svelte 5 hardening

- Key remaining each blocks.
- Replace appropriate `use:` actions with `{@attach}`.
- Convert pure effect-derived state to `$derived`.
- Move async effect state machines into controllers with explicit cancellation.
- Use `createContext` for stable app services.
- Tighten dynamic component prop types.
- Retain focused effects only for external systems such as DOM, storage, sockets and virtualization.
