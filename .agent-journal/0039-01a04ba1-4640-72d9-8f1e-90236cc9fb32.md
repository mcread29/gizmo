## The fix, inside `patches/@earendil-works__pi-coding-agent@0.84.2.patch`

In `prepareCompaction` (`dist/core/compaction/compaction.js`), before calling `findCutPoint`:

```js
let keepBudget = settings.keepRecentTokens;
const estimatedTotal = contextMessages.reduce((s, m) => s + estimateTokens(m), 0);
if (estimatedTotal > 0 && tokensBefore > estimatedTotal) {
    keepBudget = Math.min(keepBudget,
        Math.round((estimatedTotal * settings.keepRecentTokens) / tokensBefore));
}
```

The insight: `tokensBefore` is **usage-based** (real context from the provider), while the cutter's walk only sees the chars/4 message estimate. When the real context is bigger than the estimate (system prompt + tool schemas + tokenizer drift), the budget is rescaled into estimate-space so the cutter targets the same *real* share of the conversation. When there's no usage to learn from, behavior is exactly as before — so it never makes the "session too small" refusal less honest.
