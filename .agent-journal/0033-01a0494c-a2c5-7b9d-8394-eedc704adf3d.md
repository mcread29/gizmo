# Recommended minimal migration plan

1. **Do not copy the four workspace packages directly into `pi-extension.ts`.** Their entry shape is incompatible with Pi, and their `workspace:*` dependencies will not install independently.

2. **Keep Ask User as the reference implementation.**
   - Add tool and web-result tests.
   - Align Pi dependency versions with Gizmo’s patched/runtime version.

3. **Fix generic companion loading before moving UI packages.**
   - Preserve `inspectorTabs` in `load-web-extension.ts`.
   - Activate companions from enabled Pi extension identity, not only `activeDomains`.
   - Standardize every runtime entry on `gizmoWebExtension`.
   - Fix Unity’s current export mismatch.

4. **Move Svelte next.**
   - Rewrite the prompt as a normal Pi extension hook.
   - Drop the web stub unless Svelte-specific workspace labeling remains a requirement.

5. **Move or absorb Activity.**
   - Prefer making it core UI.
   - Otherwise use a no-op Pi entry plus companion bundle after the activation fixes.

6. **Move Git only after a Pi backend-to-web request/events channel exists.**
   - Rewrite `GitService` behavior into the Pi extension.
   - Move the panel and package tests.
   - Relocate `patchFileName` to generic app code or bundle it privately.
   - Then remove the static app import, server `GitService` import, special commit-message route and Git-specific store operations.

7. **Move Unity last.**
   - Move/fold `packages/unity-tools` with it.
   - Put project process/status/open/console management inside the Pi extension.
   - Expose status and console data through the planned declarative events/invoke bridge.
   - Repair and relocate the currently broken tests.
   - Remove the root Unity build hardcode and workspace dependencies only after runtime loading is verified.

8. **Remove each ID from `gizmo.extensions.json` only when its Pi replacement is active.**
   Leaving both enabled can serve duplicate web IDs and run duplicate backend behavior.

If immediate physical extraction is required before the Pi bridge is complete, the alternative is to extend `gizmo.registry.json` and `registry-manager.ts` with a second, explicitly legacy `GizmoServerExtension` artifact type. The current `pi-extension.ts` contract alone should not be stretched to pretend it supports Git or Unity’s existing server lifecycle.
