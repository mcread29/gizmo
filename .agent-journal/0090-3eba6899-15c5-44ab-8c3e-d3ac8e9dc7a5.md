## Two tiers

Mirror `resourceRoots()` (`resource-paths.ts:53`), which already establishes the global-then-project precedence chain for skills, prompts, and AGENTS.md:

```
~/.gizmo/memory/              global  — facts about the user
  facts/  KNOWLEDGE.md
  journal/                    ← only for sessions with no project

<project>/.gizmo/memory/      project — facts about this codebase
  facts/  KNOWLEDGE.md  journal/
```

The asymmetry is deliberate: **the journal is inherently project-scoped** — it records work done in a workspace. The global journal exists only to catch sessions rooted outside any project (you have 43 of those at `C:\Users\mchan`). The *facts* layer is where two tiers genuinely earn their keep.

Three rules make it work:

1. **The fact's type picks the tier.** `user` / `feedback` → global; `project` / `reference` → project. The reconciliation pass already has to classify, so this is free.
2. **Project wins on conflict.** Same precedence as skills. A project can override a global preference without deleting it.
3. **Promotion is allowed.** A session in project A must be able to write a global fact — that's how "prefers tabs" gets learned once instead of twenty times. It's the rule most two-tier designs miss, and it needs to be explicit in the extraction prompt.
