Everything after that point, the reasoning text, the final answer, and the idle state, never arrived at the page.

**Why the client did not know.** The client has no way to notice it fell behind:
- The server numbers every event per connection, but the client never reads the event id, so a gap in the stream is invisible to it.
- The `session.resume` snapshot carries no session state field. The server does emit the true state right after a resume, but nothing on the client ever re-requests a snapshot for a session it already has open. It only trusts the last `session.state` event it happened to receive.
- There is no heartbeat or "last event at" check, so a socket that stalls, a tab that gets throttled, or a reconnect that lands mid-turn leaves the page believing the last thing it heard.

So the refresh you did earlier and the "mangled" list were symptoms of the same thing: the page's picture of the session had drifted from the server's and nothing forced it back in line.

1. Add `state` to the session snapshot so a resume always tells the client whether the agent is running.
2. Have the client track the event id and re-request the snapshot when it sees a gap or after any reconnect.

The client arms a silence watch only after the first heartbeat, so servers or fakes that send none are never timed out.
